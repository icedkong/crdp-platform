# 平板与手机真机矩阵与测试用例（E24-T08）

> 任务 E24-T08（测试，3 人天，依赖 E24-T06；验收：**5 个关键页面在真机矩阵上通过**）。
> 需求依据：`docs/requirements/tech-plan.md` §15「平板与手机录入（响应式）」（NFR-RESP-001 断点与布局、NFR-RESP-002 关键页面、NFR-RESP-003 拍照上传）、`docs/design/design-system.md` §12、`docs/design/pages.md` 各页「响应式」行。
> 按 `AGENTS.md` 第 9 节：本任务交付**矩阵定义、逐页测试用例、CI 可跑的自动化用例与本执行记录表**；**物理真机上的执行由人（测试）在医院常用设备上完成**，结果记入 §6 执行记录表（同 E22-T09 渗透测试对接口径：仓库交机制，实测由人）。CI 自动化覆盖矩阵中可模拟的维度（视口档位、触控指针、旧内核能力面），见 §5。

## 1. 矩阵口径

- 关键页面（design-system §12「只有 5 个页面做响应式」）：**患者列表、患者详情、随访表单、我的任务、报告单上传与查看**（含全院报告单检索页与移动端查看器；医院 C 的植入记录、参数趋势随 M5 / E24-T10）。患者详情含**基线分节编辑**（`FollowupBaselineEdit`，pages.md §0.1 响应式「是」，E24-T09 走查补登记手机放行，真机执行时同步覆盖）。
- 兼容范围（tech-plan §15）：iOS Safari（近两个大版本）、安卓 Chrome 与主流厂商浏览器、微信内置浏览器、iPad 与主流安卓平板；**具体真机矩阵由测试与医院常用设备确定**——即本文件。
- 通过标准：每个关键页面 × 矩阵每档设备，§3 对应用例全部步骤达到预期，无阻断（页面打不开、按钮不可点、输入法挡住输入、上传失败且无重试）与高危（数据丢失、明文 / 水印缺失）问题；中低危问题入缺陷库（GitHub Issues）并注明设备档。
- 版本校准：真机系统 / 浏览器大版本随时间漂移。执行时 iOS Safari 取**执行当期最新的两个大版本**；安卓 Chrome / 厂商浏览器取近 12 个月内主力版本；微信内置浏览器（XWeb）另测一档**旧内核**（微信未升级内核的存量安装，能力面按 E24-T07 基线：无 `structuredClone` / `Object.hasOwn` / `Array.prototype.at` / `dvh`）。
- 测试数据：全部虚构（演示租户 demoa / demob 种子，姓名带「（示例）」标记，AGENTS §5.5）；不得在本机 / 靶机使用真实患者数据。

## 2. 真机矩阵（六档）

档案的唯一来源是 `frontend/packages/responsive/src/device-matrix.ts`（`DEVICE_PROFILES`，与本表一档一行对齐）；CI 用 `applyDeviceProfile` 按档案模拟，真机执行按下表选机。

| 档案键 | 设备档 | 代表机型口径 | CSS 视口（竖屏） | DPR | 指针 | 引擎能力面 | 断点档位 |
|---|---|---|---|---|---|---|---|
| `iphone-safari` | iPhone · Safari | 近两个大版本 iOS，在售主力尺寸 | 390×844 | 3 | coarse | 现代（四能力齐备） | 手机（<768） |
| `ipad-safari` | iPad · Safari（竖屏） | 近两个大版本 iPadOS，主流 11″ 档 | 820×1180 | 2 | coarse | 现代 | 平板（768–1279） |
| `android-phone-chrome` | 安卓手机 · Chrome / 主流厂商浏览器 | 近 12 个月主力版本（Chrome / 各厂商内核） | 412×915 | 2.625 | coarse | 现代 | 手机 |
| `android-phone-wechat` | 安卓手机 · 微信内置浏览器 | 微信当前版 + 一档未升级内核的存量安装 | 412×915 | 3 | coarse | **旧内核**（E24-T07 基线） | 手机 |
| `android-tablet-chrome` | 安卓平板 · Chrome（竖屏） | 主流安卓平板 | 800×1280 | 2 | coarse | 现代 | 平板 |
| `desktop-chrome` | 桌面对照 · Chrome / Edge | 1920×1080（回归对照，非真机必测项） | 1920×1080 | 1 | fine | 现代 | 桌面（≥1280） |

补充说明：

- 手机横屏、平板横屏不单独设档（档位判定只看 CSS 视口宽度；平板横屏 1180+ 仍 <1280 为平板档，iPad Pro 12.9″ 横屏 ≥1280 落桌面档，布局同桌面，抽查一机即可）。
- 微信档必测项：右上角「···」在浏览器打开（兜底链路）、返回手势不误触发表单返回、上传进度在切后台 / 弱网下的重试。
- iPhone 全面屏档同时覆盖 safe-area（Home 指示条不压底部操作栏，E24-T07 viewport-fit=cover 修复）。

## 3. 逐页测试用例（5 个关键页面）

通用前置：演示租户 demoa 种子账号（随访员 / 科主任各一）；`./scripts/dev.sh` 起本机环境，手机与电脑同网段访问医院端地址（或靶机环境，按 §1 数据口径）。每页先在桌面对照档确认功能可用，再走矩阵各档。

### 3.1 患者列表（pages.md §3；E24-T03）

| # | 步骤 | 预期（平板 768–1279） | 预期（手机 <768） |
|---|---|---|---|
| 1 | 打开「患者管理」 | 主要列（姓名、编号、病区、下次随访、状态）+ 其余列点行展开；筛选收进右侧抽屉，抽屉角标 = 已应用条件数 | 表格改卡片（姓名、状态、下次随访、病区）；筛选与高级检索进**底部**抽屉，高级检索只留常用条件 |
| 2 | 检索词检索 + 抽屉筛选（病区 / 状态 / 日期区间） | 结果、角标计数、清除筛选正确（未选全的日期区间不进筛选） | 同左；抽屉内控件触控区 ≥ 40px，数字日期不弹字母键盘 |
| 3 | 卡片 / 行操作 | 行内「详情」「录入随访」正常 | 点卡片进详情；**无批量操作**（勾选与批量条不出现） |
| 4 | 菜单与标签页 | 菜单收成图标栏、多标签页保留可横滚 | 菜单进抽屉（☰）、不显示多标签页 |

### 3.2 患者详情（pages.md §4、§4.10；E24-T04）

| # | 步骤 | 预期（平板） | 预期（手机） |
|---|---|---|---|
| 1 | 从患者列表进详情（新标签页） | 头部信息换行；页签横向滚动 | 头部折叠为「姓名 + 状态 + 下次随访」+「详情 ▾」；操作进「操作」底部抽屉 |
| 2 | 切换页签（基线 / 随访记录 / 报告单 / 沟通记录 / 操作日志） | 基线字段单列；报告单列表与预览上下排 | 页签横向滚动；随访记录、沟通记录等表格改卡片；附件（左栏导航）收成底部抽屉 |
| 3 | 报告单页签看一份报告 | 上下排布局正常，水印 `姓名（账号）· 医院 · 时间（分钟）` | 列表卡片 + 点开全屏查看器（双指缩放，水印不随内容变换） |
| 4 | 头部明文查看（有 `followup:patient:plain` 权限时） | 二次确认 + 审计照桌面口径 | 同左；60 秒自动恢复脱敏，切换后台回来也应已恢复 |

### 3.3 随访表单（pages.md §5、§5.2；E24-T02）

| # | 步骤 | 预期（平板） | 预期（手机） |
|---|---|---|---|
| 1 | 从任务 / 患者详情进随访表单 | 字段单列、标签 120px；分组条吸顶横向滚动；底部栏同桌面 | 单列、**标签在上**；输入框占满宽、高 36、字号 16；顶栏左侧为「返回」 |
| 2 | 数值字段聚焦（如 EF、LVDd） | 数字键盘（`inputmode="decimal"`） | 同左；键盘弹出时底部操作栏随可视区域（`visualViewport`），不被键盘盖住 |
| 3 | 分组跳转 | 吸顶分组条点选滚动到位（已填 / 应填，未填完橙色） | 「跳到分组」下拉 + 底部抽屉；「历史」弹层为底部抽屉 |
| 4 | 底部操作栏：上一条 / 下一条、暂存、提交 | 可用；Ctrl/⌘ 快捷键不受影响 | 触控区 ≥ 40px；有改动时点上一条 / 下一条弹「暂存并离开 / 放弃修改 / 取消」 |
| 5 | 自动保存 | 每 30 秒 + 失焦入本机草稿；每 2 分钟服务器草稿 | 同左；离线提示「离线 · 改动存在本机草稿」，离线不能提交 |
| 6 | 对比标红（A：EF 下降等） | 字段内红底 ▲，不弹窗 | 同左；悬停提示改**点击**显示（触控无 hover） |

### 3.4 我的任务（pages.md §7；E24-T05）

| # | 步骤 | 预期（平板） | 预期（手机） |
|---|---|---|---|
| 1 | 打开「我的任务」（我的待办 / 本病区 / 全部） | 主要列保留、点行进表单 | 任务**卡片**：患者（脱敏）、节点、窗口、状态、逾期标记 |
| 2 | 状态筛选 | 筛选区同桌面 | 顶部分段切换（全部 / 待随访 / 进行中 / 逾期 / 已完成）；其余条件进筛选抽屉（角标计数） |
| 3 | 任务操作 | 行内「录入」「改派」「⋮」按权限显隐 | 点卡片进表单（可录入）或只读查看（已有记录）；次操作按钮与桌面同源；**无批量改派** |
| 4 | 连续录入 | 底部上一条 / 下一条按列表顺序 | 同左（与 3.3 §4 联动，未保存弹窗） |

### 3.5 报告单上传与查看（pages.md §6.1 / §6.2 / §6.4、§12；E24-T06、E16-T05 / T06 / T10）

| # | 步骤 | 预期（平板） | 预期（手机） |
|---|---|---|---|
| 1 | 全院报告单检索（菜单「报告单与资料」） | 主要列保留 | **卡片列表**（缩略图 + 患者 / 类型 / 时间 / 位置 +N）；本页在手机放行（E24-T08 登记 `FollowupReport`） |
| 2 | 添加报告单弹窗：拍照（`capture=environment`）连拍多页 | 可用 | 弹窗全宽、内容区滚动；逐页「压缩中 → 上传中 n%」→ 进附件清单（页序 = sortNo） |
| 3 | 弱网 / 断网重试、上限 | 逐页「重试」/「移除」；超限（已上传 + 在途 > 上限）整批拦截 | 同左；切后台再回前台进度不丢 |
| 4 | HEIC（iPhone 相册默认格式） | iOS 经 input 已转 JPEG；桌面无解码器时懒加载 heic2any，仍失败按原文件上传并提示（后端 40001 白名单兜底） | 同左 |
| 5 | 位置选择与查看器 | 位置标签（超 2 个折叠 +N）；全屏查看器图片**双指缩放** 50%–500%、水印挂遮罩不随缩放错位；PDF / DOCX 用工具栏按钮 | 同左；iOS 双指只缩放图片、整页不动（gesture 拦截） |
| 6 | 扫码上传（电脑端生成二维码） | — | 手机扫码进 H5（15 分钟一次性令牌）：位置预选（模板版本一致才预选）、拍照压缩（同链路）、提交即创建报告单，过期 40101 提示 |
| 7 | EXIF 隐私 | 上传的 JPEG 不含 GPS 定位（画布重编码） | 同左（可用查看文件属性 / exif 工具抽查） |

## 4. 未适配页面对照（负向用例）

手机（<768）打开未适配页（字段字典、随访计划配置、导入、统计、系统设置、平台端）：整页显示 MobileBlocker「请在电脑或平板上操作」；平板打开不拦截（可横向滚动）。锁定用例：`device-matrix.spec.ts`（守卫段）。
