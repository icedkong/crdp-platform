## 3. 复测流程（修复版本 → 复测 → 结论回写 → 关闭 / 打回）

1. **准入**：修复 PR 已合并、CI 绿；新版本过 §5 A 组冒烟后由运维发 UAT（版本冻结口径，手册 §3）；复测在该修复版本上进行并记录版本号。
2. **复测**：按 Issue 的「复现步骤」原文重走（同角色、同入口；涉数据范围的用对照账号交叉验证，如 K-1 跨病区对照）；同时重走该发现波及的 §5 用例（修复手册分诊时注明的组）；「预期」以 Issue「预期（按需求 / UAT 脚本）」列为准，不引入新口径。
3. **结论**：三选一（§4）；当日在复测清单 CSV（§5 模板）记一行——复测记录与执行记录表同口径（截图编号存 UAT 共享目录，不入仓库）。
4. **回写**：`scripts/uat_retest.py --apply` 把结论回写为 Issue 评论（含幂等标记 `RETEST-ID: <UAT-ID> #<轮次>`、复测环境与修复版本、证据引用）并按结论执行关闭 / 打开；打回的 Issue 由原修复任务（Issue 正文标注）重新处置，修复后复测走 `--round 2` 起的新轮次。
5. **关闭判据**：阻断 / 严重必须**复测通过**才 closed；一般全部有处置结论（复测关闭，或医院书面接受的延期上线＝遗留关闭）；建议入库跟踪（可不复测，triage 归类后直接关闭或留跟踪）。看板核验见 §7。

## 4. 复测结论三档与关闭动作

| 结论 | 判据 | Issue 动作（uat_retest.py） | 记录要求 |
|---|---|---|---|
| **通过** | 按原复现步骤不可复现，行为符合「预期」列；波及用例重走通过 | 评论 + **关闭（completed）** | 修复版本 + 复现步骤重走结果 + 证据（复测记录行 / 截图编号） |
| **不通过** | 仍复现，或修复引入新问题（新问题另开 `UAT-W{周}-{序}` 入库，不混单） | 评论 + **保持打开（已关闭则重开）**，评论路由原修复任务 E23-T09 / E23-T10 | 仍复现的描述 + 证据；打回后修复再测走新轮次 |
| **遗留（延期上线，书面接受）** | 仅**一般 / 建议级**；修复代价大于影响，医院方 UAT 负责人书面接受（阻断 / 严重不允许遗留——判据 2 清零） | 评论 + **关闭（not planned）** | 处置结论 + 期限 + 医院确认留痕；随遗留项清单进签字单附件（手册 §7 判据 4） |

复测结论与 uat_intake 的分级映射共用同一套 label 梯子（OQ-122②）；清单校验强制「通过必须带修复版本与不可复现描述」「不通过必须带复现描述」「遗留必须带处置结论与期限且级别为一般 / 建议」，防结论口径漂移（工具自检锁定，§8）。

## 7. 闭环判据与看板

- 「UAT 缺陷复测关闭」以缺陷库 Issue 状态为证（手册 §7 判据 2 的数据来源）：label `UAT` 的 Issue 中 severity:high / medium 全部 closed（＝修复 + 复测通过），severity:low 全部 closed（复测关闭或遗留关闭）或有处置结论，severity:info 全部入库；
- `scripts/uat_retest.py --status` 随时输出该看板（按 severity 汇总开 / 关与未关闭清单，直接给出判据 2 判定行）；一般级未关闭项提示「须有处置结论（关闭，或医院书面接受的延期上线处理）」，最终判读由测试 + 产品在 W35 签字确认会前核对；
- 本手册 §6 预演发现不进缺陷库（仓库内留痕即复测证据，同修复手册 §6 口径）；窗口内发现复现同类问题时按其 `UAT-ID` 走 Issue 流程，预演记录作交叉引用。
