## 1. 目标与验收口径

- 「冒烟用例通过」= §3 用例集**全部通过**：E23-T11 §6 切换动作完成后**立即执行**（runbook §3 时间线、§8 衔接「§6 动作 1 的验证即首个用例」）；机器可判定子集在 CI 每次构建执行（§7），生产侧动作按 §4 由人执行留痕；

## 4. 生产冒烟执行流程（切换完成后立即，60 分钟）

1. **时点与人**：E23-T11 runbook §6 动作 5（通知医院方）之后、动作 6（观察期）之前；测试执行，运维 / 实施在场，医院 A 管理员配合账号；
2. **数据红线**：只使用带「示例」标记的虚构患者（S-5 / S-8 各 1 名，建议命名「赵冒烟（示例）」「钱跟进（示例）」）；**不打开真实患者明文**、不修改真实患者、不在真实患者上记沟通 / 上传 / 导出（`AGENTS.md` §5.5）；冒烟结束删除冒烟患者并在执行记录确认；
3. **顺序**：S-0 → S-12 按编号执行（S-6 依赖 S-5 患者、S-12 汇总当日留痕放最后）；每条记「通过 / 不通过」+ 证据（截图编号，存运维 wiki 共享目录，不入仓库）；
4. **通过判据**：13 条全部「通过」；S-0 失败 = 切换未生效，立即回 runbook §7「切换后」路径评估入口回切，不继续往下执行。

## 6. 失败处置与升级

- **S-0 / S-1 失败**（切换未生效）：runbook §7 切换后路径——入口回切（DNS 摘除 WAF CNAME）停止用户访问 → 修复验证 → 重新开放；已导入数据不回滚；
- **S-2~S-12 失败**：按阻断级入 hypercare 台账（GitHub Issues，label `HYPERCARE`，P0 = 15 分钟响应，`docs/ops/hospital-a-hypercare.md` §3）；影响主链路时同上评估入口回切；
- **机器侧（CI `GoliveSmokeIT`）失败**：不进生产窗口——runbook §3 时间线纪律「不带病上线」，修复复绿后再排切换；
- 每次中止 / 回切记入 §5 执行记录与上线评审材料（runbook §7 末条口径）。

## 7. 自动化对照（CI 恒跑）

- **`GoliveSmokeIT`**（`backend/crdp-server/src/test/java/com/crdp/server/followup/GoliveSmokeIT.java`）：S-2~S-12 机器可判定部分的端到端冒烟——demo 租户 `demoa` + V123 预置账号矩阵（科主任 `a.cvs1.dir`、病区医生 `a.cvs1.doc01`、随访员 `a.cvs1.nur01`、数据录入员 `a.fu.clerk01`），四角色登录 → 列表脱敏 → 示例患者登记（重复病案号 40902 拦截）→ 自动入组与当期任务 → 认领提交按时完成 → 未联系到跟进 + 站内信 → 报告单上传归档 → 首页卡片 → 越范围 40400 / 跨端 40300 → 当日审计；门控 `CRDP_IT_MYSQL_PORT`（CI 与本机 docker compose MySQL 13306 同口径），自建自清（标记 `IT-E23T12`），全部虚构数据（`AGENTS.md` §5.5）；
- **`scripts/check_golive_smoke.py`**：本手册用例表 ↔ IT 用例锚点（S-x）↔ runbook §8 互引 ↔ `docs/README.md` 索引 ↔ ci.yml 接线的防漂移校验，CI 恒跑；
- 生产冒烟（§4）不在 CI 运行，由测试按手册在场执行。
