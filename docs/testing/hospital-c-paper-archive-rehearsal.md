# 医院 C 历史纸质资料导入演练：执行留痕（W43 · E23-T27）

> 任务 E23-T27（测试，2 人天，依赖 **E21-T10** ✅〔随访编号自动生成与历史患者建档，PR #231〕；验收：**历史患者建档与扫描件关联核对通过**）。关联需求 **C-PAT-008**（历史患者建档）；评审用例 **C-ACC-30**（`docs/reviews/hospital-c-acceptance-review.md` §3.5）：历史患者建档（过去植入日期、手填原编号）→ 上传扫描件并关联 → 建档数与关联数核对通过。技术执行 / 回滚与切换面复用 A 口径（`docs/ops/hospital-a-import-rehearsal.md`、`docs/ops/hospital-a-go-live.md` §C 上线切换）；医院侧真实纸质台账的扫描与人工复核不在本任务（产品 / 医院配合，随 E23-T23 UAT 与 E23-T26 切换）。

## 1. 验收口径

- 「历史患者建档与扫描件关联核对通过」= 演练三阶段在**测试环境形态**（随包产品配置链激活后的医院 C，demoa 化身）一次通过，且核对三口径一致：
  1. **建档**：12 名历史患者（2015–2024 纸质档案 10 名 + 近期植入 2 名，全部虚构）以过去植入日期 + 手填纸质原编号（`纸C-IT27-*`）登记成功——建档数（库内计数）= 台账行数；纸质原编号逐名落库；按器械类型自动入组（V86 预置映射 → V91 预置计划，起算快照 = 植入日期）；
  2. **任务口径（Q14 / C-PAT-008）**：历史患者（窗口已全过）不建任何任务、全库 OVERDUE 不增；近期植入（35 天 / 100 天）恰建 1 条当期任务（术后 1 个月 ±7 / 术后 3 个月 ±14，日期逐项落库核对），已过窗口（术后 72 小时）不建、未来窗口不预生成；重复纸质编号 40902 + DENIED 审计（防重复建档）；
  3. **扫描件关联**：按台账逐名上传扫描件并关联（纸质随访表 / 知情同意书 ONE_PER_FILE 挂基线「基本信息」、植入手术记录挂植入记录整条 + 器械信息分组〔E21-T32 锚点〕、多页随访表 MERGE 合并一份、出院小结名称级「无需录入」覆盖）——核对三口径：台账（源）= 库内（rpt_report / rpt_report_link / rpt_report_file / sys_file ATTACHED + 电子化状态默认值）= API（患者内清单份数 / fileCount / 位置标签 + 概览待录入扫描件数〔C-PAT-010〕）；按纸质编号全院检索只命中本人（C-SCAN-014 核对入口）；越患者植入位置 40400（关联防错）。
- 门控 `CRDP_IT_MYSQL_PORT`（CI 起 docker compose 注入端口；本机先 `docker compose up -d`）；激活态（开关 / 预置类型 ENABLED / 预置计划 PUBLISHED）在收尾还原随包默认，A / B 惰性口径与其他 IT 不受影响。
- 任一核对不过 = 验收不通过，修复后整组复测。
