1. **按里程碑顺序做**：M0 → M1 → M2 → M3 → M4 → M5 → M6。同一里程碑内按 `tasks.csv` 的行序（即排期开始顺序）取任务；只有当一个任务的“依赖”列全部完成后才能开始它。
2. **只做开发类任务**：类型为“后端 / 前端 / 全栈”的任务由代理实现；“运维”任务中涉及华为云账号、真实云资源（CCE、RDS、OBS、ELB、WAF、等保）的部分**不要自己执行**，只能产出脚本 / IaC / 文档草稿并交给人；“测试”任务代理可以写自动化用例；“产品”任务（配置、UAT、医院沟通）交给人。
3. **仓库现状（2026-10-31）**：M0 工程骨架已完成本地部分——Maven 多模块（E01-T02）、前端 pnpm 工作区双应用（E01-T03，注意不是上游 Vben，见 OQ-01）、GitHub Actions CI（E01-T04 的单测 / lint 部分）、docker-compose 本地 MySQL + Redis、子域名 / 租户编码路由的 hello 接口（E01-T09 的本地版本）、两个演示租户库 `t_demoa`、`t_demob`。云资源（E01-T05 SWR、E01-T06 IaC、E01-T07 RDS、E01-T08 OBS、E01-T10 生产密钥注入）尚未做，由人负责。
4. 开始一个任务前先读：该任务“关联需求”在 `docs/requirements/` 中的条目与验收标准、相关页面的 `docs/design/pages.md` 小节、相关接口的 `docs/api/` 小节。
5. 任务完成标准见根目录 `AGENTS.md`“完成定义”。提交说明里写任务编号与需求编号，例如 `feat(followup): E15-T01 任务状态流转 [A-FU-003 A-FU-010]`。
6. 关键路径：E02 → E07 → E11 → E14 → E15 → E19。这些任务不要拖。
7. 标记“超出里程碑窗口”的 19 个任务是排期算法算出的顺延风险，不代表可以不做。
