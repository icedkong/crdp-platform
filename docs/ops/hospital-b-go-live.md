> 任务 E23-T19（运维 · 全栈 2，0.5 人天，依赖 **E23-T17** B 验收；验收：**B 上线**）。tasks.csv 本行未关联需求编号：上线面 = 复用 `docs/ops/hospital-a-go-live.md` 全套口径（闸门 → 核对 → 切换 → 回滚）+ `docs/requirements/hospital-a-spec.md` 第 14 章「医院 B 配置差异」（B 需求与 A 相同，**无历史数据导入**）。
> 按 `AGENTS.md` 第 9 节：运维任务涉及真实云资源与生产操作的部分**不由仓库侧执行**——切换评审、平台端操作、通知医院与观察期值班由持账号的运维 / 实施 / 平台管理员在场完成；本 runbook 是他们照着走的**切换手册**，配套交付 CI 防漂移校验 `scripts/check_hospital_b_golive.py`（§11）。机器侧锚点为**引用型**（§11，不新建 IT）。
> 衔接：E23-T15（B 租户开通，配置与 A 一致）→ E23-T16（B 预置计划激活）→ E23-T18（用户 / 病区 / 角色）→ **E23-T17（B 验收：补录任务与节点随访率，本任务硬前置）** → **E23-T19（本任务）** → E23-T28（B 回归：A 不受影响）、医院 B 观察期（hypercare 口径滚动）、E23-T20 起 C 上线准备（E23-T26 切换仍复用 `hospital-a-go-live.md` 全套口径）。

## 1. 目标与验收口径

- 医院 B 正式上线：§4 就绪终检全绿 → §5 切换动作完成 → §6 B 冒烟通过 → §5 动作 6 观察期启动，医院 B 用户开始正式使用。
- 验收判据「B 上线」拆成三件可判定的证据：
  1. **切换完成**：§5 动作清单全部勾选（入口连通性核对、租户状态 = 已启用、到期配置与合同一致、通知医院 B、观察期启动）；
  2. **冒烟通过**：§6 冒烟用例集（BG-0~BG-10）全部「通过」，数据红线遵守（只用「（示例）」虚构患者、不碰真实患者明文），示例患者删除确认；
  3. **留痕**：§7 切换与冒烟记录归档运维 wiki（仓库不留生产数据，AGENTS §5.5）。
- 与 A 上线（E23-T11，`hospital-a-go-live.md`）相比的三处**差异（复用其口径下的减法）**：
  1. **无正式数据导入**：第 14 章 B 差异清单没有历史数据导入需求（约 5000 名患者宽表导入 A-PAT-018 属医院 A，E23-T05~T07 / T11 链路 B 不适用，B 也没有对应任务）——A 册 §4 正式数据交接与 §5 生产导入执行、汇总数与抽样两级核对**整体不适用**，以 §4 就绪终检（配置与行为核对）替代；
  2. **生产入口复用**：B 与 A 共用医院端入口 `https://<医院端域名>`（登录请求体带 `tenantCode` 区分租户，`docs/api/auth.md`），入口已随 A 上线开放（A 册 §6 动作 1 的 DNS → WAF CNAME）；本任务**无 DNS 切换动作**，只做入口连通性核对（B 租户编码可登录、走 WAF→ELB→CCE 全链路，`docs/ops/cce-prod.md` §7 口径）；
  3. **转正已随开通完成**：B 租户已按 E23-T15 `hospital-b-onboarding.md` §4 步骤 5 转正（TRIAL → ENABLED，PLT-TEN-010，与 A 上线转正同口径）；本任务核对状态与 `TENANT_STATUS` 审计在册，若现场仍为 TRIAL（转正未执行）按 A 册 §6 动作 2 补转正后再继续（补转正也是 `DISABLE` 回滚路径的前提，见 §8）。

## 8. 中止与回滚

- **切换前（终检不过 / 闸门不全绿）**：顺延窗口；配置类问题按源头手册处置——计划激活类走 `docs/ops/hospital-b-plan-preset.md` §4（停用 B 预置 / 复制新版本再发布），配置一致性类走 `docs/ops/hospital-b-onboarding.md` §5.1 差异处置，用户 / 病区类走 `docs/ops/hospital-b-user-ward-role.md` §4；B 尚无正式患者数据，极端时整租户重来成本可控（E05-T08 注销口径，`hospital-b-onboarding.md` §7）。
- **切换后（发现阻断问题）**：**租户级收敛，不回切平台入口**——平台入口医院 A 在用，A 册 §7「切换后」的 DNS 回切会同时停掉医院 A，对 B 不适用；改为平台端 `POST /api/platform/tenants/{tenantId}/status`，action=DISABLE，填原因（PLT-TEN-010 / PLT-TEN-016：即吊销 B 全部在线会话、登录闸门按租户状态拒绝、定时作业扇出不再含 B、数据不动）→ 缺陷修复与验证 → action=ENABLE 恢复（停用 → 启用，PLT-TEN-013 / 017 口径）。**A 不受影响**：整套动作只动平台库 B 租户行与 B 会话。
- **数据不回滚**（A 册 §7 同口径）：上线后 B 已有真实使用痕迹时，任何数据修复走字段历史与缺陷流程，不回滚删除；极端情况（数据损坏）走 `docs/ops/tenant-restore.md` 时间点恢复，须先停写入并通报医院方。
- 每次中止 / 回滚记入 §7 记录与上线评审材料；冒烟与观察期问题按 `docs/ops/hospital-a-hypercare.md` §3 SLA 入台账（P0 15 分钟响应）。
