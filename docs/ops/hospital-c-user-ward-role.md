# 医院 C 科室、病区、用户与角色配置 runbook（W41 · E23-T22）

> 任务 E23-T22（产品 · 产品，1 人天，依赖 **E23-T20** C 的 97 个字段与两套计划配置；验收：**用户按科室病区分配**）。
> 需求依据：`docs/requirements/hospital-c-spec.md` §7 科室病区隔离（C-WARD-001 科室沿用平台科室树 + 病区 / 中心独立字典；C-WARD-002 患者归属一个科室和一个病区；C-WARD-003 医生、随访员、护士可负责多个科室或病区，沿用 A-WARD-002；C-WARD-004 角色数据范围在 A-WARD-003 基础上增加「本人负责科室」；C-WARD-005 后端强制过滤；C-WARD-007 租户管理员全院；C-WARD-008 停用与权限预览）+ §10 建议角色模板（医生 / 随访员 / 护士 / 科主任的数据范围、主要权限与敏感权限列）。
> 按 `AGENTS.md` 第 9 节：生产侧的科室 / 病区 / 用户 / 角色录入（按交接单）由 C 租户管理员 / 实施在场完成，本 runbook 是他们照着走的**配置手册**；仓库交付预置种子（tenant/seed V137，local / dev / IT 演示与核对用）、行级核对（`CPresetWardUserSqlTest`，CI 恒跑）与落库演练 IT（`CPresetWardUserVerifyIT`，门控 CRDP_IT_MYSQL_PORT，demob 作 C 化身）。
> 衔接：E23-T20（C 字段与计划预置）→ E23-T21（C 报告单类型与映射）→ **E23-T22（本任务）** → E23-T23（C UAT 组织）、E23-T26（C 上线切换）。与 E23-T20 / T21 无先后依赖（用户配置不触碰字段 / 计划 / 报告单行）。

## 1. 目标与验收口径

- 医院 C 的科室（平台科室树结构）、病区 / 中心字典、业务角色（含科室病区数据范围）与用户按科室病区分配配齐：医生 / 随访员 / 护士按负责的病区或科室查看数据（C-WARD-003），负责心内科的科主任可见归属心内科的全部患者、不论这些患者在哪个病区（§7 验收原文），多科室 / 多病区 / 科室 + 病区混合都取并集（§7 业务规则），每个病区 / 中心有默认随访负责人（C-WARD-001 / A-FU-009 沿用）。
- 验收判据「用户按科室病区分配」拆成三件可判定的证据：
  1. **预置行随包且与规格逐项一致**：tenant/seed V137 进入演示 / IT 的每个租户库（OQ-93 ①/② 口径），行级参数由 `CPresetWardUserSqlTest`（CI 恒跑）锁定——角色矩阵 14 医生 / 6 随访员 / 4 护士 / 3 科主任、科室 2 个（心内 + 心外，C 自有虚构取值）、病区字典 3 病区 + 2 中心、敏感项（211 明文 / 212 导出 / 217 删除患者 / 229 修改已提交 / 230 删除记录 / 232 下载）不预授；
  2. **按科室病区分配的行为**：心内一病区医生检索只见本病区患者、直接访问他病区患者 40400；心内科科主任跨病区见本科室全部患者、他科室 40400；跨科室主任见两科室并集；病区 + 科室混合医生见两分支并集——由 `CPresetWardUserVerifyIT`（demob 化身，门控）走通，另核权限预览可见病区 / 科室与来源角色（C-WARD-008 沿用 A-WARD-009）；
  3. **生产录入路径**：C 租户管理员按交接单经科室 / 病区 / 角色 / 用户页录入或批量导入（§3），抽查判据同 2。
- 生产库**不执行种子**（TenantSchemaMigrator 只在 local / dev / demo 剖面带 seed 目录）：真实身份不入库是红线（AGENTS §5.5），V137 的 27 名虚构账号不进生产 C 库，生产由 §3 录入真实用户。

## 2. 载体与口径（为什么放种子、为什么与 V123 / V136 并存）

- 用户账号与科室 / 病区取值是**租户自有序数据**：C 的取值只能由 C 侧自建——本任务交付的 V137 是该口径的**参考实现与演示数据**，与 A 预置 V123（E23-T04）、B 预置 V136（E23-T18）同目录同构（OQ-93 ①）。
- 种子对每个租户库执行同一脚本（V100 / V123 / V136 同口径，OQ-93 ② / OQ-128 ③）：各演示租户库都带 A、B、C 三套预置，命名空间互不相交（`a.`/`b.`/`c.` 账号、`W-A-`/`W-B-`/`W-C-` 病区码、`DEPT-C-` 科室码、`A_`/`B_`/`C_` 角色码），`CPresetWardUserSqlTest.coexistsWithAAndBPresetsInSharedSeedDatabases` 锁定不串。
- C 业务角色复制自 §10 建议角色模板（PLT-ORG-005 模板角色不可直接分配）：医生 / 随访员 / 护士 / 科主任四个角色码 C 前缀；菜单授予按 §10「主要权限」矩阵，敏感项不预授。
- **与 A / B 预置的两处结构差异**（C 规格 §7 / §10 的 C 自有口径，OQ-144）：
  - 临床三角色（医生 / 随访员 / 护士）数据范围 = **本人负责病区（WARD）+ 本人负责科室（RESPONSIBLE_DEPT）**——C-WARD-003「可负责多个科室或病区」按 §7 规则两类分配都生效、取并集；只配病区的用户行为与 §10「本人负责病区」逐字一致（未分配科室则科室分支为空）；
  - 科主任 = **本人负责科室（RESPONSIBLE_DEPT，C-WARD-004 新增类型）**，不再配全部病区（ALL，全院留给内置租户管理员，C-WARD-007）；负责范围多一张科室分配表（`sys_user_dept_scope`，用户编辑页「负责科室」多选）。
- 医院 C 的功能开关（implant / eri_cycle / record_edit_submitted / record_sequence_no 等）不随本种子变更（种子对每个租户库执行同一脚本，不写租户分支）：演示库保持 V100 随包状态，生产 C 库按上线配置开启（OQ-136①、OQ-143② 口径，E23-T26 上线切换核对）。

## 3. 生产配置执行（C 租户管理员 / 实施，W41）

前置：租户开通编排完成（C 租户 TRIAL/ENABLED、角色模板与权限点已随模板落地）；交接单（医院 C 提供：科室清单、病区 / 中心清单与别名、用户清单·账号·姓名·工号·角色·负责科室与病区、各病区默认随访负责人）已经医院 C 确认。真实姓名与工号只进 C 租户库，不进仓库、不进文档（AGENTS §5.5）。

| # | 步骤 | 入口（医院端） | 判据 |
|---|---|---|---|
| 1 | 维护科室树 | 系统管理 → 组织与科室（PLT-ORG-002） | C 自有科室（如心内科、心外科）落库启用；患者登记与科主任科室范围都指向它（C-WARD-001/002） |
| 2 | 录入病区 / 中心字典 | 系统管理 → 病区管理 → 新建（编码 / 名称 / 类型 / 别名 / 排序） | 编码本院唯一、创建后不可改（A-WARD-001 沿用）；历史写法进别名（A-WARD-006 值映射）；起搏器程控随访中心等中心类 ward_type = CENTER |
| 3 | 建业务角色并配数据范围 | 系统管理 → 角色管理 → 从模板复制（医生 / 随访员 / 护士 / 科主任）→ 数据范围 | 医生 / 随访员 / 护士 = 本人负责病区 + 本人负责科室（C-WARD-003 并集），科主任 = 本人负责科室（C-WARD-004）；「仅本人负责的患者」按需加选；敏感项（明文 / 导出 / 删除患者 / 下载）不预授 |
| 4 | 录入用户并分配角色 | 系统管理 → 用户管理 → 新建 / 批量导入（E06-T07 / E06-T08）→ 分配角色 | 每人至少一个业务角色；首登改密策略按医院要求 |
| 5 | 按科室病区分配（验收主判据） | 用户管理 → 编辑 → 负责科室多选 + 负责病区多选（C-WARD-003） | 医生 / 随访员 / 护士按交接单勾选负责科室和 / 或病区（两类取并集）；科主任只配负责科室；跨病区、跨科室、科室 + 病区混合都支持 |
| 6 | 配默认随访负责人 | 病区管理 → 各病区 / 中心 → 默认随访负责人 | 每个病区 / 中心都配，负责人是负责本病区的随访员（A-FU-009 兜底与逾期抄送按此解析） |
| 7 | 敏感权限按 §10 默认值补配 | 平台侧先放开「修改已提交记录」（PLT-SCOPE-004，plt_sensitive_perm）→ 角色管理 → 分配 229 | §10 医生敏感列「修改已提交记录（默认分配，可调整）」：平台放开后配给医生角色；明文 / 导出按需逐人分配 |
| 8 | 抽查 | 用交接单中的账号登录 | 病区医生只见负责病区患者；负责心内科的科主任见归属心内科的全部患者（不论病区）；他病区 / 他科室 40400（§7 验收）；抽查记录归档运维 wiki，不含患者数据 |

- 失败停留：某科室 / 病区 / 用户与交接单不符 → 当场改配重查；角色误配敏感项 → 角色页移除（会话下次请求即失效，权限版本递增）。
- **A / B 不受影响**：本节全部动作只写 C 租户库。

## 4. 回滚与处置

- 用户配错科室 / 病区：用户编辑页改选即生效（C-WARD-003 分配或取消立即生效，权限版本号递增）；范围为「本人负责病区 / 科室」但两类都未分配的用户看不到患者，页面提示联系管理员（§7 规则）。
- 人员离职 / 停用：用户停用（不删除，保留审计关联）；病区撤并：病区下仍有在随访患者时不能停用，须先转出（C-WARD-006 转科室病区随患者迁移，A-WARD-008 首期口径）。
- 整批配错重来：批量导入的错行按导入校验报告修正后重导（E06-T08 幂等口径）；角色停用即从会话收回，不需要删角色。
- 中止上线：C 尚无正式患者数据时，科室 / 病区 / 用户 / 角色配置可整租户重来（走 E05-T08 注销口径的成本评估）。
