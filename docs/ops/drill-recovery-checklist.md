## §4 清单逐项核对方法

| # | 清单项（runbook §4） | 机器核对（化身 / 存档，工具执行） | 生产由人核对（持云账号在场执行） |
|---|---|---|---|
| 1 | 恢复点三态标记（数据丢失量的直接证据） | 恢复租户库 `fu_saved_filter` 三态标记：M0（跨区域同步前）= 1、M1（跨区域同步后）= 0、M2（区域内同步后）= 0；演练报告 `verdicts.proofs` = PASS（`--proof-file` 同口径含标记行与审计链行条件） | 同左（SQL 由工具生成口径，`--proof-file` 同格式） |
| 2 | 迁移历史随库恢复 | 恢复库 `flyway_schema_history` 非空；成功版本集 = 仓库脚本版本集（`db/tenant/base` + `followup` + `seed`）且 = 源库快照时刻版本集（恢复点早于最新版本时应用启动自动补齐，属预期） | 应用启动 Flyway 校验通过（无 Validation 失败告警） |
| 3 | 注册表 | 恢复平台库 `plt_tenant_resource`：全部行 `jdbc_url` 指向备用区域实例、无故障区域（cn-north-4）地址残留；演练租户行 `db_name` 与恢复库一致 | 清单外租户行人工抽查（脚本改写命中数 ≥ 1 且残留 0） |
| 4 | 健康检查 | 化身口径 = 演练报告记录 `verified_at` 与验收门判定全 PASS、实测 RPO/RTO 与里程碑重算一致 | 备用区域入口 `/actuator/health` 返回 UP（`--health-url`） |
| 5 | 医院端登录与冒烟（虚构测试数据） | 机器侧数据前提：恢复库逐表行数与跨区域副本基线一致（导入完整性，86 表） | 登录 → 写一条随访记录 → 查询可见；明文查看、报告单预览水印正常 |
| 6 | DEW 密钥跨区域可用 | 机器侧数据前提：注册表 `password_cipher` / `secret_mode` 随库恢复非空（应用重启后可取得连接信息） | 应用能解开 `password_cipher` 并连上租户库（连不上 = runbook §2 前置缺失，如实记录问题项） |
| 7 | 对象对齐（tech-plan §14「与数据库恢复时间点对齐」） | 清单对象（恢复点前上传：rpt-m0、rpt-c0）全部在备用区域副本且**内容逐字节一致**（报告单预览取回一个对象的化身）；恢复点后对象（rpt-m2）不入副本与清单；报告 `verdicts.objects` = PASS | `obsutil ls` 抽样 + 报告单预览实际取回一个对象 |
| 8 | 审计链完整 | ① 恢复库 `aud_log` 全部封存行按内容 SHA-256 重算通过（0 处 BAD_HASH，含源库由 Java `AuditChainWriter` 封存的存量行——工具内置 v1 规范化串镜像，列序与 `AuditChainTable.java` 静态对齐）；② 链行指纹 `(id, prev_hash, hash)` 与跨区域快照逐行一致（恢复不引入新空洞、无改动无缺失）；③ 演练写入链段（源库尾行 → C0，同步前）衔接且重算通过；④ 恢复点后链行（C1，同步后）不在（该段数据本就丢了，属预期） | 验链作业 SUCCESS 或人工验链 SQL：恢复点处链值连续；恢复点后链值缺失属预期。演示库存量链空洞来自 IT 自清理（`AuditTableMaintenance` 预期行为），完整链连续性由验链作业对真实环境校验（PLT-AUD-009） |
| 9 | 定时作业恢复执行 | 平台库 `shedlock` 表随库恢复（结构在，调度骨架未丢） | ShedLock 正常抢锁、随访计划生成等作业无异常堆积（作业日志） |

工具输出逐项 PASS/FAIL；任一机器核对项 FAIL 以非零退出（CI 阻断），不得手工改库凑验证
（runbook §4 失败处置）。

## 化身核对口径说明（OQ-125 延续）

- 恢复数据核对的化身环境与 E22-T07 §6 相同（compose MySQL 8.0、逻辑快照化身备份副本、
  `xrga_/xrgi_/xrgb_` 前缀化身库、虚构数据），「重建 / 恢复」由 `cross_region_drill.sh`
  local-drill 模式执行，本工具不重复实现演练流程，只做核对；
- 审计链行 C0 / C1 由工具按后端 v1 规范化串（`AuditChainTable` + SHA-256，与 Java
  `URLEncoder` 逐字节对齐，`--selftest` 含编码边界用例）写入并衔接源库封存链尾——
  恢复点对链的截断因此有了直接证据（C1 不在）；
- 演示库自带 700+ 条 Java 写入的封存链行，每次 `--drill` 都会用镜像逐行重算，
  后端调整链格式（列序 / 编码 / 摘要算法）而未同步工具时立即 FAIL。
