# 安全设计方案（等保 2.0 三级 · 仓库草稿）

> E22-T13 资料四类之一（清单 `README.md` M-07）。现场提交版以本草稿为底稿，由产品定稿（M-14~M-16 口径，OQ-133）。
> 需求依据：`docs/requirements/platform-spec.md` NFR-CMP-001（等保 2.0 三级，已确认）与 NFR-SEC-001~009、
> `docs/requirements/hospital-a-spec.md` A-NFR-007（沿用平台等保三级设计；短信与 Webhook 不含患者敏感信息）、
> `docs/requirements/tech-plan.md` §4（安全与密码应用）与 §2 部署表、§14（审计与备份容灾）。
> 标准框架：GB/T 22239-2019《网络安全等级保护基本要求》第三级。

## 1. 定级对象与系统边界

- **定级对象**：临床科研数据一体化平台（crdp）——多租户医院随访 SaaS，部署于华为云华北-北京四（cn-north-4）。
  定级对象含：医院端 Web（web-hospital）、平台端 Web（web-platform）、手机拍照上传 H5、后端服务
  （crdp-server 单一可部署包，CCE 2 副本）、平台库 `crdp_platform` 与每院一个租户库 `t_{租户编码}`
  （RDS for MySQL 8.0 主备实例）、DCS Redis、OBS（业务桶每院一个 + 审计归档 WORM 桶）、DEW/KMS。
- **安全保护等级**：第三级（GB/T 22240-2020 定级流程；定级报告与备案受理见清单 M-01 / M-02，E22-T01 已执行）。
- **边界与接口**：公网入口仅 WAF → ELB → CCE 一条链路（医院端按 `{租户编码}.平台域名` 子域名、
  平台端独立域名）；出网仅 NAT 网关 + 固定 EIP 调用腾讯云短信 API（HTTPS，内容不含患者信息，A-NFR-007）；
  云控制面（IAM / CBH 堡垒机）为运维通道；第三方边界（短信服务商、华为云托管服务）在本方案中按
  「云侧责任共担 + 供应链管理」处理（P-11）。
- **环境矩阵**：开发、测试（含 UAT 与渗透靶机，全部虚构数据）、生产三套；生产数据不出生产环境
  （`AGENTS.md` §5.5：种子、测试、示例不得含真实数据）。

## 2. 总体架构（安全视角）

单一 Spring Boot 模块化单体（CCE 2 副本跨可用区打散，容器非 root 运行）+ 一个 RDS 主备实例
（平台库 + 全部租户库，跨可用区半同步）+ DCS Redis + OBS + DEW/KMS。租户数据库隔离、
数据范围默认拒绝、字段脱敏与明文专用接口、只追加审计链构成应用层四道安全边界
（`AGENTS.md` §5.1~§5.4，`docs/requirements/tech-plan.md` §5）。链路、端口与信任域见 `network-topology.md`。

## 3. GB/T 22239-2019 三级技术要求逐项设计

### 3.1 安全物理环境（云侧责任共担）

平台全部计算、存储、网络资源使用华为云公有云托管服务（CCE / RDS / OBS / ELB / DCS / DEW），
物理环境的机房场地、供电、电磁防护、设备物理访问等控制点由云服务商承担并持其等保备案与
测评结论（责任共担，`docs/ops/pentest.md` §3 口径）；本项目侧的义务是选择合规云服务与区域
（北京四）、经 CBH 堡垒机与 IAM 管理云控制面访问（P-06），并把云服务清单纳入资产台账（M-15）。

### 3.2 安全通信网络

- **网络架构**：VPC 内划分 ELB 子网 / 应用子网 / 数据子网；应用 2 副本跨可用区（cn-north-4a/b），
  RDS 主备跨可用区（半同步，可靠性优先切换），关键链路无单点（`iac/cce-prod/cce-baseline.json`、
  `iac/rds-prod/params-baseline.json` 为事实源，CI 防漂移）。
- **通信传输**：全链路 TLS 1.2+（ELB 套件 `tls-1-2-fs-with-1-3` 前向保密、80 仅跳转 443、HSTS；
  WAF 侧 TLS v1.2 + `cipher_2`）；RDS 内网连接亦开 SSL（`ssl_enable=true` + JDBC `useSSL=true`）。
  出网调用（短信）走 HTTPS。NFR-SEC-001。

### 3.3 安全区域边界

- **边界防护**：华为云 WAF 云模式阻断（基础防护、Webshell、扫描器 / 爬虫、CC、黑白名单、精准防护全开）；
  ELB 安全组对公网仅开放 80/443；节点回源安全组仅接受 ELB 安全组 → NodePort 30080；
  RDS 白名单只放行本集群节点安全组（最小开放，`docs/ops/cce-prod.md` §2）。
- **入侵防范**：WAF 阻断事件、HSS 企业版（漏洞管理 + 安全基线〔等保三级检查模板〕+ 入侵检测，
  每节点一席）、前端依赖漏洞扫描（CI `pnpm audit --prod`，高危阻断）与后端镜像 Trivy 扫描
  （HIGH/CRITICAL 阻断）、上线前第三方渗透测试（W32–W35，`docs/ops/pentest.md`；
  自查高危 0、中危全部有处置结论，`docs/ops/pentest-remediation.md` / `pentest-remediation-frontend.md`）。
  Webhook 地址禁止内网与回环（防 SSRF）。NFR-SEC-006。
- **访问控制（边界侧）**：节点密钥对登录、无公网 IP；运维通道统一 CBH 云堡垒机（P-06）。

### 3.4 安全计算环境

按三级控制点逐项（证据指向与现状判定详见 `self-assessment.md` §2.4）：

| 控制点 | 设计与落地 |
|---|---|
| 身份鉴别 | 口令策略（≥8 位、3 类字符、不含账号、90 天有效期、历史 5 次不重复）、失败 5 次锁定 30 分钟、3 次起图形验证码、口令 Argon2id 存储（`SecurityConfig`）、平台账号强制双因素（短信 / OTP）、医院端 / 平台端空闲超时 30 / 15 分钟、绝对会话 12 小时、H5 一次性令牌（`docs/requirements/platform-spec.md` §7 安全策略参数，已确认） |
| 访问控制 | 权限码 `{模块}:{资源}:{动作}` + 后端统一鉴权（缺权限 40300）；有效权限 = 已开通模块 ∩ 平台允许范围 ∩ 角色并集；数据范围默认拒绝（受控表无 `@DataScope` 即缺陷 40302，范围为空追加 `AND (1=0)`，越范围单对象 40400）；租户只来自登录令牌，`TenantRoutingDataSource` 按租户选池、无租户上下文拒绝访问（租户库表不带 `tenant_id`，NFR-SEC-003/004） |
| 安全审计 | 登录、增删改、配置 / 权限 / 状态变更、明文查看、导出、打印、下载、批量查询、被拒绝操作全部审计；与业务同事务 INSERT，运行账号对审计表只有 INSERT/SELECT；每分钟链值封存（HMAC-SHA256）+ 每日验链告警；在线 12 个月，之后分区导出 JSONL.gz 归档 OBS WORM 桶（合规模式 15 年，对象级保留同步设置，`docs/ops/audit-worm-archive.md`）；敏感值只存摘要（PLT-AUD 系列） |
| 入侵防范 | 见 §3.3；应用层最小化：API 文档 prod profile 默认关闭、CORS 白名单 fail fast、短信回执 Basic Auth（渗透自查修复项，`docs/ops/pentest-remediation.md` §4） |
| 恶意代码防范 | 上传文件真实类型白名单、拒绝可执行 / 脚本 / 启用宏的 Office / 压缩包、大小与数量限制；HSS 主机入侵检测；**上传病毒扫描首期不做**——该控制点预期「部分符合」，说明材料与后续方案见 `docs/requirements/tech-plan.md` §10 残余风险 2（约 1.5 人周，M6 整改窗口） |
| 数据保密性 | 敏感字段（姓名、病案号 / 病历号、电话、住址）应用层 AES-256-GCM 加密 + HMAC-SHA256 盲索引，每院数据密钥、信封加密（`CryptoService` / `CryptoTypeHandler`，NFR-SEC-002、A-NFR-003）；列表不逐行明文，明文走专用接口（敏感权限 + 二次确认 + 审计），前端明文 60 秒自动恢复脱敏、不落 localStorage；OBS 业务桶 SSE-KMS；云盘与备份 AES-256 |
| 数据完整性 | 审计链值防篡改（见上）；文件 SHA-256 校验；Webhook / 导出水印码 HMAC-SHA256 签名；导出预览统一脱敏；数据库变更只经 Flyway（只新增不改旧，`check_flyway_versions.py`） |
| 数据备份恢复 | RDS 自动全量 + Binlog（每 5 分钟上传，区域内 RPO ≤ 5 分钟）保留 30 天；跨区域备份北京四 → 上海一（E22-T04）；每院每日逻辑备份（应用侧加密存 OBS）；单院恢复到指定时间点（`docs/ops/tenant-restore.md`）；跨区域重建演练实测 RPO / RTO（`docs/ops/cross-region-drill.md`，目标 RTO ≤ 4 小时），半年一次 |
| 剩余信息保护 | 敏感字段内存态明文用后即弃（前端 60 秒恢复脱敏；后端明文仅请求内）；H5 一次性令牌用后失效；会话令牌 30 分钟可刷新、绝对 12 小时；磁盘 / 对象不残留：生产数据不进开发测试环境，样本入仓前脱敏（`scripts/deidentify_sample.py`，E23-T05） |
| 个人信息保护 | 患者个人信息的收集限于随访业务必需（字段字典驱动）；展示默认脱敏、明文逐字段专用接口 + 审计；短信与 Webhook 不含患者敏感信息（A-NFR-007）；导出须敏感权限 + 审批（科主任导出须租户管理员审批）；数据主体范围按病区隔离 |

### 3.5 安全管理中心

- **统一运维通道**：生产 kubectl / 节点 SSH / 数据库管理全部经 CBH 云堡垒机（运维审计），
  生产数据库禁止直连（NFR-SEC-007，P-06）。
- **集中日志**：应用与审计日志入 LTS，日志带 tenantId 可按租户检索（NFR-OPS-001）；
  应用日志禁止输出完整证件号与手机号（NFR-SEC-005）。
- **集中监控告警**：CES 覆盖核心接口错误率、作业失败、RDS 复制状态、WAF / HSS 事件
  （E22-T03，排期 W2–W3 验收 2026-11-23）；审计验链作业失败即告警。
- **审计链集中校验**：每日验链作业 + 告警（见 §3.4 安全审计行）；归档清单（行数、首尾序号、链值）
  供归档后完整性复核。
- **平台租户视角**：平台账号进入租户视角受角色授权、规则版本固定、高敏变更双人复核、
  只写平台审计（NFR-SEC-008/009），属「平台对租户数据的管理通道」集中管控。

## 4. 密码应用与密评预留

首期按等保三级建设，使用国际通用算法，不使用国密（`docs/requirements/tech-plan.md` §4 已确认）：
AES-256-GCM（字段加密，每院数据密钥，信封加密）、HMAC-SHA256（盲索引 / 审计链 / 签名）、
SHA-256（文件与审计完整性）、Argon2id（口令）、TLS 1.2+（传输）；需要非对称时 ECDSA P-256 或 RSA-3072。
所有加解密、签名、摘要只经密码服务组件（`CryptoService` 族），业务代码不直接调算法库；密文带版本 /
算法 ID / 密钥版本，新旧算法可并存——**为将来密评整体切换国密（SM4-GCM / HMAC-SM3 / SM2 / TLCP）预留**
（切换路径：新算法写入 → 双列并存 → 后台重加密作业 → 校验后切换；数据密钥每年轮换，旧版本保留解密）。
密钥分级：KMS 每院一个主密钥 → 按用途数据密钥（字段 / 盲索引 / 文件 / 审计），密文存租户库、
运行时内存缓存；云凭据（数据库 / OBS / DEW / 签名密钥）经 DEW 凭据管理注入，不进镜像、不进 Git（P-04）。
