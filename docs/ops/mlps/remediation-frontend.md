## 2. 处置流程（Issue → 关闭）

1. **分诊**（问题入库当日）：核对测评记录表 / 报告章节引用（`evidence_ref`）→ 在 UAT 级环境（浏览器
   真机 + H5 手机）复现或核对代码 / 配置；确认资产归属（backend / frontend / infra / management，路由错误
   在 Issue 评论改派）；复核结论与分级（不符合 / 部分符合 × 高 / 中 / 低；误报与申辩结论留 Issue 评论，
   onsite-assessment.md §5）。
2. **处置决策**（高风险通报后 24 小时内、其余 2 个工作日内）：按 §3 三选一定结论；接受风险须产品确认
   （评论区留痕）；需要改权限模型 / 数据模型 / 安全边界的先升级 `docs/open-questions.md`（AGENTS §10），
   不发明需求。
3. **整改**：一类问题一个分支 / PR（提交说明 `fix({scope}): E22-T16 {MLPS-ID} {标题}`），PR 关联 Issue；
   **TDD——先写失败测试锁定问题行为再修**（本轮 D-01 前端面即此口径，§4 表列测试名）。
4. **复测**（E22-T17，W45）：由测评机构按原核查点复测（或窗口外由测试按同步骤回归），结论回写 Issue
   并同步 `self-assessment.md` §4 偏差登记（onsite-assessment.md §7 闭环）。
5. **关闭**：高风险必须复测通过才 closed；中风险在处置结论 + 整改落地（或缓解控制生效）后 closed；
   低风险排期跟踪。E22-T18 汇总闭环记录随备案材料提交。
