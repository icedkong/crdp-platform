## 2. P-01 安全管理总纲

- 目标：保障临床科研数据一体化平台（等保三级定级对象）的信息保密性、完整性与可用性，
  满足 GB/T 22239-2019 第三级管理与技术要求及医疗数据相关法规。
- 范围：平台研发、测试、运维、运营全过程；华为云北京四生产环境与全部三套环境；
  全体开发（2）、测试（1）、产品（1）及外部测评 / 渗透合作方。
- 责任分工：产品——制度发布与对外合规衔接（定级备案、测评合同、医院沟通）；
  开发——应用安全机制实现与修复；测试——安全测试与验收；运维（持云账号）——云侧配置、
  基线核验、备份与演练执行。安全事项无明确责任方时由产品牵头会诊。
- 评审与发布：制度每年评审一次；重大变更（等保测评整改、架构变化、法规更新）触发即时修订。
  修订在仓库进行（本文件），发布版本由产品定稿签署。

## 3. P-02 人员安全管理

- 入职 / 参与项目前签署**保密协议**（外部合作方另签 NDA，渗透测试见 `docs/ops/pentest.md` §2）；
- 按角色最小授权：仓库协作者、云 IAM 账号、堡垒机账号逐人开立，禁止共享账号；
- 转岗 / **离职**当日内回收：IAM 账号停用、堡垒机授权撤销、仓库协作者移除、生产会话强制下线；
  平台侧账号操作记平台审计；
- 全员知悉数据红线：不得将真实患者数据带出生产环境（`AGENTS.md` §5.5）；
- 安全意识：新成员上岗前阅读 `AGENTS.md` 与本制度；测评与渗透窗口内的人员名单实名登记（M-04 / M-17）。

## 4. P-03 账号与权限管理

- 业务系统：账号实名唯一；有效权限 = 已开通模块 ∩ 平台允许分配范围 ∩ 角色并集；
  敏感权限（明文查看、导出、删除、下载）默认不可分配，由平台放开（tech-plan §5）；
- 管理类账号（平台账号、租户管理员）强制**双因素**（短信 / OTP）；
- 云侧：IAM 人员账号 + 委托授权，禁止使用账号级 AK/SK 长期凭证；OBS 归档桶使用专用子账号只授该桶；
- 会话治理：医院端 / 平台端空闲超时 30 / 15 分钟、绝对会话 12 小时；管理员可强制下线
  （`tenant:session:kick`）；密码重置后其他会话全部失效；
- 定期复核：每季度由产品组织权限复核（平台角色、租户管理员、堡垒机与 IAM 授权清单），留痕存档。

## 5. P-04 密码与密钥管理

- 口令：≥8 位、至少 3 类字符、不含账号、90 天有效期、历史 5 次不重复；失败 5 次锁定 30 分钟；
  初始与重置口令随机生成经短信下发、首次登录强制修改（platform-spec §7，已确认）；
  口令 Argon2id 存储（`SecurityConfig`）。
- 密钥分级：DEW/KMS 每院一个主密钥 → 按用途数据密钥（字段 / 盲索引 / 文件 / 审计）；
  数据密钥以密文存租户库，运行时仅内存缓存；**密钥轮换**每年一次，旧版本保留用于解密，
  重加密走后台作业（`CryptoReencryptionJob`，切换与双列并存口径见 tech-plan §4）；
- 凭据管理：数据库 / OBS / DEW / 签名密钥等凭据全部经 DEW 凭据管理或 K8s Secret 注入，
  **不进镜像、不进 Git、不进文档与日志**（`AGENTS.md` §5.5）；证书私钥经 `TF_VAR_*` 环境变量注入不落盘。

## 6. P-05 数据安全管理

- 脱敏与明文：敏感字段默认按字段策略脱敏返回；明文只能专用接口逐字段获取，需敏感权限
  + 二次确认 + 写审计；前端明文 60 秒自动恢复脱敏、不落 localStorage（`AGENTS.md` §5.3）；
- **导出**管控：导出、下载、打印为敏感权限且全部审计；科主任导出须租户管理员审批；
  报告单下载需 `followup:scan:download` 且写审计；平台租户视角导出默认拒绝（NFR-SEC-008）；
- 环境数据红线：种子、测试、示例、截图一律「（示例）」虚构值；生产数据不出生产环境；
  医院样本进仓库前必须脱敏（`scripts/deidentify_sample.py`，E23-T05）；
- 数据保留：患者与随访数据服务期内长期保留、只软删除（A-NFR-008）；审计在线 1 年、
  归档 WORM 保留 15 年；短信与 Webhook 不含患者敏感信息（A-NFR-007）。

## 7. P-06 运维管理

- 运维通道：生产 kubectl / 节点 SSH / 数据库管理**全部经 CBH 云堡垒机**（会话审计）；
  **生产数据库禁止直连**（NFR-SEC-007）；
- 变更管理：生产变更（IaC apply、镜像发布、配置调整）走 runbook（`docs/ops/`）+ 变更评审；
  数据库结构变更只经 Flyway 新增脚本（见 P-10）；维护窗口默认北京时间 22:00–23:00
  （`docs/ops/rds-prod.md` §2.1）并提前通知租户；
- 发布与回滚：滚动发布 maxUnavailable=0；发布前 CI 全绿；异常按各 runbook 回滚预案执行
  （单院恢复 `docs/ops/tenant-restore.md`、上线回滚 `docs/ops/hospital-a-go-live.md`）；
- 日常巡检：观察期按 hypercare 两册巡检项执行；常态巡检以 CES 告警为主（E22-T03 落地后）。

## 8. P-07 备份与恢复管理

- 备份策略：RDS 自动全量 + Binlog（每 5 分钟上传）保留 30 天；跨区域备份北京四 → 上海一
  保留 30 天（E22-T04）；每院每日逻辑备份（应用侧加密存 OBS）；OBS 业务桶版本控制 + 跨区域复制；
- 保留与删除：备份不手工删除；审计归档受 WORM 保护不可删改（保留期内）；
- **演练**：单院恢复与跨区域重建**每半年至少一次**，实测 RPO / RTO 并出具报告存档
  （`docs/ops/cross-region-drill.md`、`docs/ops/drill-records/`；验收口径区域内 RPO ≤ 5 分钟、RTO ≤ 4 小时）；
- 恢复授权：单院恢复等破坏性操作须运维执行 + 产品知会，全程留痕（runbook 验证清单）。

## 9. P-08 应急管理

- 应急矩阵：运维 1 名 + 后端 1 名 + 产品 1 名（姓名与电话在授权书附件 / 值班表维护，不入仓库，
  `docs/ops/pentest.md` §5、hypercare §3 同口径）；
- 分级与响应时限：P0 15 分钟 / P1 30 分钟 / P2 2 小时 / P3 1 个工作日（hypercare §4 时限表）；
- 预案：入口不可用（WAF / ELB / CCE 排查，cce-prod §5）、数据损坏（单院恢复 tenant-restore）、
  区域不可用（跨区域重建 cross-region-drill）、安全事件（渗透窗口应急口径 pentest §5：
  发现入侵迹象立即停止测试 → 联系应急矩阵 → 按需回滚）；
- 事件记录：GitHub Issues 台账（分级 label）+ 复盘；对外（医院）沟通由产品统一归口。

## 10. P-09 安全事件与漏洞管理

- 渗透测试发现全量入缺陷库（GitHub Issues，`PENTEST-ID` 幂等 + `severity:*` 标签，
  `scripts/pentest_intake.py`）；**高危即报即修**（当日通报、通报后 24 小时内入库、修复 PR 关联
  Issue、复测通过才关闭）；中危 2 个工作日内给三选一处置结论（修复 / 缓解 / 接受风险，接受须产品确认）；
- 持续扫描：前端依赖 `pnpm audit --prod`（HIGH/CRITICAL 阻断，例外须登记白名单）、
  后端镜像 Trivy（HIGH/CRITICAL 阻断，未发补丁 CVE 只报不阻）；SWR 镜像扫描；
- 主机与边界：HSS 漏洞与安全基线检查（等保三级模板）发现不合规项按 `docs/ops/cce-prod.md` §6
  记录处置；WAF 阻断事件留存；
- 等保测评问题（E22-T14 输出）进入同一缺陷流程，整改与复测对齐 E22-T15~T17。

## 11. P-10 开发安全管理

- 编码规范与红线：`AGENTS.md` 第 5 节（租户隔离、数据范围默认拒绝、脱敏与明文、审计、
  种子数据红线、Flyway 纪律、功能开关、表单模板驱动、权限码、乐观锁）；
- 评审：一个任务一个分支 / PR；安全边界改动（权限模型 / 数据模型）须先升级
  `docs/open-questions.md`；
- 测试门禁：CI 全绿才可合并——后端 spotless + 全量测试（含跨租户隔离、数据范围用例）、
  前端 format / lint / test / build、依赖与镜像扫描（见 P-09）；
- 数据库变更：只经 **Flyway** 新增脚本、平台库与租户库版本不重复（`check_flyway_versions.py`）、
  不手工改库、不用 JPA 自动建表；
- 文档同步：接口与 `docs/api/` 一致；新疑问进 open-questions。

## 12. P-11 云服务与供应链管理

- 云服务清单：华为云（CCE、ELB、WAF、RDS、DCS、OBS、DEW/KMS、HSS、CBH、LTS、CES、NAT、
  SCM、SWR、IAM）+ 腾讯云短信；真实实例与资产台账见拓扑正式版（M-15），纳入资产清单管理；
- 责任共担：物理环境与云平台自身安全由云服务商承担（其等保资质与结论归档）；
  本平台侧责任为配置基线与账号权限（`security-design.md` §3.1）；
- 供应链来源：基础镜像与依赖只用官方源 / 公共仓库并锁定版本（pnpm-lock、Maven 坐标）；
  镜像存 SWR 私有仓库并开扫描；不接受医院提供的样例原件入库（脱敏后才可，E23-T05）；
- 服务商变更：短信 / 云服务替换须经产品确认并更新本清单与拓扑。

## 13. P-12 审计与日志管理

- 审计范围：登录、增删改、配置 / 权限 / 状态变更、明文查看、导出、打印、下载、批量查询、
  平台租户视角访问、被拒绝的操作全部入审计（`AGENTS.md` §5.4、`docs/api/audit.md`）；
- 只追加：审计表无修改与删除接口，运行账号仅 INSERT / SELECT；每分钟链值封存
  （HMAC-SHA256）+ 每日验链告警（`AuditChainWriter` / `AuditChainVerifier`）；
- 归档留存：在线 12 个月，分区导出 JSONL.gz 归档 OBS WORM 桶（合规模式 15 年），
  归档与演练口径见 `docs/ops/audit-worm-archive.md`；
- 日志脱敏：应用日志禁止输出完整证件号与手机号（NFR-SEC-005）；日志与异常不写口令、
  令牌、患者明文；LTS 日志带 tenantId 可按租户检索（NFR-OPS-001）；
- 审计查询：租户审计租户库内查询；平台访问记录只存平台审计库（NFR-SEC-009）。
