## 制度

`management-policies.md`：安全管理制度汇编草稿（P-01 总纲 ~ P-12 审计与日志），每项制度给出
目标与范围、管控规则、**仓库机制锚点**（可评审、机器可验的部分）与**由人签署 / 执行**的部分。
现场提交的盖章版（M-14）以本草稿为底稿；制度与实际运行的一致性由 `self-assessment.md` 管理层面逐项核对。

## 拓扑

`network-topology.md`：生产网络拓扑（占位符版）——入口链路（DNS → WAF → ELB → CCE）、
跨可用区部署、信任域与最小开放端口矩阵、数据面与运维面组件、跨区域容灾（北京四 → 上海一）、
三套环境与「生产数据不出生产环境」红线。事实源为三份 IaC 基线 JSON 与
`docs/ops/cce-prod.md` §1 / `docs/ops/rds-prod.md` §1（CI 防漂移）；真实 ID / 域名由人替换（M-15）。

## 安全设计

`security-design.md`：安全设计方案——定级与系统边界、总体架构、按 GB/T 22239-2019 三级
技术五类（安全物理环境 / 安全通信网络 / 安全区域边界 / 安全计算环境 / 安全管理中心）逐控制点
的落地措施与证据指向；管理类要求指向制度汇编；密码应用与密评预留（国际算法 → 国密切换路径）。
与自查记录联动：每条控制点在 `self-assessment.md` 有对应判定（符合 / 部分符合 + 整改）。

## 自查记录

`self-assessment.md`：等保 2.0 三级自查记录（十个安全要求分类逐项判定）——仓库基准日
2026-11-12，判定口径「符合 / 部分符合（附整改计划）/ 待落地已排期 / 由人核验（云上）」；
已知偏差如实登记（恶意代码防范部分符合（tech-plan §10 残余风险）、审计归档无异地副本（已确认接受）、
OQ-123 / OQ-127 / OQ-42 / OQ-39 暂行口径），不粉饰全绿；证据指向仓库真实路径（CI 校验存在性）。
