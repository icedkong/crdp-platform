# 文件扫描启用、补扫与异常文件处置（OQR-08）

本手册为部署 / 操作草稿。2026-11-20 本地代码已落实，真实 ClamAV、签名更新、CCE 网络及容量须由持账号运维核验（OQR-10）；本轮不执行云操作，不以单测替代病毒引擎验收。

## 生产上线前置

生产 `application-prod.yml` 默认 `clamd`，`CRDP_CLAMD_HOST` 缺省为空，必须显式配置；端口默认 3310。生产显式 `off`、未知模式、空地址、非法端口、非有限或超过 60 秒的连接 / 读取超时拒绝启动。启动只校验配置；运行时扫描不可达、协议异常、超时则上传返回 50300，写 `FILE_SCAN_UNAVAILABLE`，写任何文件对象之前拒绝，不降级为禁用扫描。开发 / CI 可显式 off，台账只能是 UNSCANNED。

部署顺序：先在受控网络准备 clamd / freshclam 与签名，再应用迁移 V147、发布后端并观察上传与补扫。不得为了启动成功将生产模式改成 off。现有 KMS 等生产闸门保持有效，不绕过它们验证本项。

1. 服务在平台内网运行，网络策略仅允许业务工作负载访问 clamd TCP，不暴露公网；clamd TCP 本身不提供加密 / 身份认证。患者文件不得发送到云沙箱或外部在线查毒站点。
2. 对齐 `StreamMaxLength`、`MaxScanSize`、`MaxFileSize`、归档递归及扫描超时与平台最大合法上传大小；超限必须报错，不能把未完整扫描当干净。用目标版本验证 `AlertExceedsMax` 等策略及超限样本，结果记入发布证据。
3. 签名按部署策略更新，失败和过期告警接入既有运维监控。引擎只使用 `zINSTREAM` 分块协议；客户端只接受完整 `stream: OK`，异常 / 截断 / 过长应答为失败。连接和读超时均有限，另有整次不超过 60 秒的连接关闭期限，避免写阻塞或慢速应答无限等待。
4. 使用独立非患者测试文件验证干净文件通过、官方 EICAR 测试样本拒绝、停服务返回 50300 且对象 / 台账未落地；恢复服务后正常上传。记录引擎版本、签名日期、环境、时间、配置、响应及审计，不把测试病毒文件纳入仓库或患者资料库。

协议依据：[ClamAV 官方协议](https://docs.clamav.net/manual/Usage/ClamdProtocol.html)。实际病毒库 / 安全策略验收仍是人工前置。

## 补扫队列与准确进度

迁移 V147 只增加 `virus_scan_attempts`、`virus_scan_attempted_at`、`virus_scan_retry_reason` 及索引；不修改历史结论，不把 UNSCANNED 批量变 CLEAN。已有 V139 不修改。

每天北京时间 03:20，按租户作业框架逐库执行；单趟默认 200，配置上限限制在 1–1000。未尝试的先处理，其余按最近尝试时间 / ID 排序。每行先记尝试，再核对租户对象前缀、对象存在和 SHA-256：

| 结果 | 状态与操作 |
|---|---|
| 内容与哈希一致且引擎通过 | CLEAN，写扫描完成时间，清除重试原因 |
| 引擎检出 | INFECTED，写完成时间和 `FILE_VIRUS_FOUND`，原件保留 |
| 哈希不一致 | HASH_MISMATCH，写完成时间和 `FILE_VIRUS_HASH_MISMATCH`，不猜病毒结论 |
| 对象缺失 / 前缀异常 / 扫描失败 | 保持 UNSCANNED，分别记 OBJECT_MISSING / FOREIGN_KEY / SCAN_UNAVAILABLE，下一轮重试 |

UNSCANNED 保持既有访问权限 / 范围规则，本项不把“未扫”伪装为“已验证安全”，也不擅自新增全量禁用历史附件的规则。

单文件失败继续处理后续文件，汇总写失败审计，作业框架登记本租户本趟 FAILED；不是“批次全通过”。未扫描行的 `virus_scanned_at` 保持空。原子状态守卫保证已完成结论、已删文件不被补扫覆盖；并发未完成尝试仍可能多扫一次，不会把异常结果回改 CLEAN。失败行轮转到队尾，不能永久阻塞新文件。扫描关闭时作业不扫描，无“已扫”结论。

获授权运维通过堡垒机 / 既有数据库只读账号，在选定的单租户库运行 `deploy/checks/file_scan_progress.sql`，记录执行人工单与时间；不要给 Web 用户数据库凭据。结果只含文件 ID、状态、计数、时间和原因码，无文件名、患者字段或对象键。第一组汇总展示未扫 / 干净 / 异常数量，第二组最多 200 条待重试或待处置记录；需要更多时按 ID 继续分页。该入口不改库、不触发扫描，也不具有放行或下载能力。作业状态和审计通过既有管理入口核对。

## 异常文件处置入口

INFECTED / HASH_MISMATCH 在预览授权、下载签发、实际取流时拒绝（40400，不暴露对象存在）；下载读取对象后再次检查，防止补扫在读取期间完成却返回旧字节。旧短时链接同样受状态闸门约束。异常下载写 `FILE_UNSAFE_DOWNLOAD_DENIED`，不包含文件名或患者字段。已交付内容无法追溯回收。

本项采用**逻辑隔离**：原件留在原对象键，业务预览 / 下载闸门禁止访问，不自动移动或删除证据。处置入口为上述只读清单 + 安全事件工单；由开发、产品及医院信息科共同判断临床影响。工单须记录租户、文件 ID、结论与依据、审批人员、时间和相关审计 ID，不附患者明文。安全分析需要读取证据时由既有获授权安全运维流程执行并审计，不能经业务下载接口绕过闸门。

确认需从业务中删除时，获 `followup:scan:delete` 的医院账号使用已有报告单 / 附件删除接口并填写原因，生成既有删除审计；这是软删除，不物理清除证据。暂不删除则继续保留逻辑隔离并在工单登记负责人。对象缺失 / 归属异常先核查恢复与租户前缀，不能猜对象键。**没有“手动标为 CLEAN”或跳过引擎的放行入口**；误报解除或证据物理销毁涉及新的安全处置决议，另行确认，不改扫描结论假装完成。
