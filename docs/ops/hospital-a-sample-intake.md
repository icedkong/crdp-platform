# 医院 A 历史数据样本接收与脱敏对接手册（W34）

> 任务 E23-T05（全栈，3 人天，依赖 E18-T05；验收：**医院提供的样本经脱敏后校验通过**）。
> 需求依据：`docs/requirements/hospital-a-spec.md` A-PAT-018（宽表历史数据导入）与 §4「宽表历史数据导入流程」；`docs/requirements/tech-plan.md` §12（导入管道）。
> 按 `AGENTS.md` 第 9 节：**与医院的样本交接、真实数据核对、迭代修正由产品 / 实施在场执行**（§8 列清单）；仓库交付对接机制——本手册、脱敏工具（`scripts/deidentify_sample.py`，CI 自检恒跑）、单元 / 集成核对用例（`DeidentifiedSampleValidateTest` / `DeidentifiedSampleIntakeIT`）。
> 后续：E23-T06（导入演练 · 数据核对，约 5000 名患者）、E23-T07（导入演练 · 技术执行与问题修复）、E23-T11（正式导入与上线切换）。窗口 W34（2027-07-05 当周）。

## 1. 目标与口径

- 目的：医院 A 现有系统的历史随访数据是宽表 Excel（一个患者一行，`9 前置列 + 212 基线列 + N 组 × 54 随访列`，医院样例 N = 10、共 761 列，Q05 / A-PAT-018）。本任务打通「医院样本 → 脱敏 → 导入预检」链路，并确认医院样本经脱敏后**预检 0 错误**。
- 验收口径拆解：
  - **医院提供样本**：医院从原系统导出宽表 Excel（导出口径见 §3），经安全渠道交付（不进仓库、不进聊天工具，§4）；
  - **经脱敏**：`scripts/deidentify_sample.py` 把标识列（患者编号 / 病案号 / 姓名 / 电话1 / 电话2）替换为虚构值（§5），产出可进测试环境的脱敏样本；
  - **校验通过**：脱敏样本上传租户 `demoa` 导入向导，预检到达 PRECHECKED 且 **errorCount = 0**（错误阻断提交，confirm 40001；警告是人工复核清单，可导入，§6）。
- 单元与集成核对在仓库里常跑：`DeidentifiedSampleValidateTest`（单元：真实 V38 字典 + V123 病区预置下 0 错误）、`DeidentifiedSampleIntakeIT`（集成：工具子进程真跑 + 导入向导 HTTP 全链路预检 0 错误，门控 `CRDP_IT_MYSQL_PORT`，CI 覆盖）。

## 2. 链路总览

```
医院原系统导出（宽表 xlsx，仓库外）
  → scripts/deidentify_sample.py（版面核对 + 标识列替换 + 写后自检；§5）
  → 脱敏样本 xlsx（仓库外，测试环境可收）
  → 导入向导上传（医院端 web-hospital「患者管理 → 导入」；E18-T06 同链路）
  → 预检（流式解析暂存 + 按字段字典校验，E18-T02 / T03）
  → 校验报告：errorCount = 0 → 校验通过（警告按 §6 分类处置）
  → （E23-T06 / T07 / T11 才确认提交：分批写入 + 历史记录生成 + 可按批回滚，E18-T05）
```

## 3. 医院侧：样本导出口径（产品 / 实施与医院约定）

| 项 | 口径 | 原因 |
|---|---|---|
| 格式 | 原系统导出的宽表 xlsx，一张工作表（名称不限，惯用「患者数据」） | 宽表版面适配按单工作表识别（A-PAT-018 流程 1–2） |
| 列结构 | 前 9 列为前置列（序号、患者编号、病案号、姓名、性别、手术年龄、入院日期、诊断分类、数据完整度），其后 212 基线列、再后 N 组 × 54 随访列 | 表头按位置逐列对位，列数或表头对不上整体报错、不做猜测 |
| 单元格 | 全部按**文本**导出；日期 `yyyymmdd`（或 `YYYY-MM-DD`）、日期时间 `yyyymmddHHMM` | 导入管道「单元格一律按文本读入」（tech-plan §12）；Excel 日期**序列号**形态（数值单元格）读出来是数字文本，预检会报类型错误——请医院导出为文本，或在预检报告里按错误修正 |
| 空值 | 空白或 `N/A`（精确写法，不做大小写变体猜测） | 两者导入侧都归一为空值 |
| 脏值 | 照原样导出（「0/1」的是否类、如「6颈动脉内剥」的编码+文字、超提示范围数值） | 不要求医院先清洗——Q36 / Q37 / 软范围由校验报告分列处置（§6），口径已与医院确认（Q36 / Q37） |
| 病区 | 医院现行写法（病区名 / 编号 / 历史别名） | 走病区字典与别名映射（E18-T04 / A-WARD-006）；未映射值是**错误**，须修正原表或先在病区管理配别名 |

## 4. 样本交接与保密（红线）

1. 医院样本是**真实患者数据**：文件、截图、映射表永不进入仓库（AGENTS §5.5；工具内置护栏：仓库内路径直接拒绝）；不进聊天工具与邮件正文，走约定的加密渠道（如医院文件交换平台），交接双方登记；
2. 脱敏在**本机 / 实施机**离线完成：`deidentify_sample.py` 不联网、不打印任何原值（只打印各列替换计数）；`--map-out` 映射表（原值 ↔ 虚构值，用于追溯）只允许写到仓库外，且与样本同密级保存，用后按医院要求销毁；
3. 脱敏后的样本只进**测试环境**（虚构值不回写医院、不用于任何统计分析——数据形状真实但标识已虚构）；
4. 预检报告（批注版 Excel）含原值列（敏感列脱敏展示，OQ-101③），与样本同密级流转。

## 5. 脱敏工具：`scripts/deidentify_sample.py`

```bash
# 仓库根目录执行；输入输出都在仓库外
python3 scripts/deidentify_sample.py /secure/医院样本.xlsx -o /secure/脱敏样本.xlsx
# 可选：固定 salt 复现同一映射（salt 不泄露原值；默认随机并打印到 stderr）
python3 scripts/deidentify_sample.py /secure/医院样本.xlsx -o /secure/脱敏样本.xlsx --salt <本次窗口约定值>
# 可选：映射表（仅仓库外，追溯用）
python3 scripts/deidentify_sample.py /secure/医院样本.xlsx -o /secure/脱敏样本.xlsx --map-out /secure/映射表.tsv
# 自检（CI 恒跑）：内置虚构样本走全流程
python3 scripts/deidentify_sample.py --selftest
```

行为与护栏：

| 环节 | 行为 |
|---|---|
| 版面核对 | 与后端 `WideLayoutAdapter` 同口径：前置 9 列 + 基线锚点（来自迁移 V38 的「原表列名」，当前 212 列）+ N 组 × 54 随访锚点；对不上**整体报错不做猜测**，差异清单带列字母 |
| 标识替换 | 前置列「患者编号 / 病案号 / 姓名」+ 基线敏感锚点列（V38 `sensitive_flag=1`：病案号、姓名、电话_1、电话_2）；**同一列族内同一原值 → 同一虚构值**（前置列与基线列保持一致，避免「前置列与基线列不一致」警告）；空白与 `N/A` 不是标识值，原样保留 |
| 虚构值形态 | 病案号 `S` + 6 位序号、患者编号 `L` + 6 位、姓名「姓 + 示例 + 两位序号」（如 `王示例01`）、电话 `1390000` 示例号段——全部带可辨识虚构标记（规则 5）；编号按 HMAC(salt) 排序分配，不同原值必不同编号（5000 名患者量级无碰撞） |
| 不动的列 | 序号、数据完整度（不导入）、性别 / 年龄 / 日期 / 诊断 / 病区与全部临床值（校验要用） |
| 写后自检 | 重读输出：行列形状不变、非标识单元格逐格一致、标识列无原值残留；任何一条不满足即报错退出，输出视为无效 |
| 护栏 | 输入在仓库内 / 映射表在仓库内 / 输出覆盖输入 → 直接拒绝 |

## 6. 预检与「校验通过」判据（导入向导，E18-T06）

上传脱敏样本后看校验报告（向导第 3 步；`GET /api/hospital/followup/imports/{jobId}/issues`，批注版报告可下载）：

- **errorCount = 0 才算「校验通过」**（有 ERROR 时确认提交被拦，40001）。常见 ERROR 与处置：

| 错误 | 原因 | 处置 |
|---|---|---|
| TYPE | 单元格格式不符（最常见：Excel 日期序列号、数值列填了文本） | 医院**重新导出为文本**或修正原表，再走 §5 重新脱敏上传（可多次重新导入） |
| OPTION_MISS | 取值不在字典选项内 | 医院修正原表；或产品确认属字典缺项 → 走字段字典变更（新迁移，不改旧脚本） |
| WARD_UNMAPPED / WARD_DISABLED / WARD_AMBIGUOUS | 病区值映射不上 / 病区停用 / 一值多区 | 在病区管理维护别名映射或恢复病区（E18-T04 / A-WARD-006），无须改样本 |
| MRN_BLANK | 病案号为空 | 医院补齐（无法关联与查重） |
| 布局错误 | 列数 / 表头对不上 | 核对导出口径（§3），整文件重出，不做猜测 |

- **警告（WARN）是人工复核清单，不阻断**——医院样本的预期脏值按已确认口径自动处置：

| 警告 | 口径 | 复核动作 |
|---|---|---|
| BOOLEAN_01（Q36） | 是否类填「0/1」→ 按**空值导入** | 导入后按报告清单补录 |
| OPTION_CODE_TEXT（Q37） | 「编码 + 文字」→ 取**编码导入**，文字存该字段备注 | 复核备注，必要时修正 |
| SOFT_RANGE | 超出提示范围（可导入） | 逐条人工复核 |
| REQUIRED_EMPTY | 必填为空（历史导入口径只提示，完整度按未填计算） | 无须处理，完整度由系统重算（A-PAT-019） |
| DUP_FILE / DUP_EXISTING | 文件内重复 / 系统已存在 | 确认提交时选「更新」或「跳过」（A-PAT-018） |
| DERIVED_MISMATCH | 派生字段原值与重算不一致 | 导入以重算结果为准（A-FLD-005） |
| FRONT_MISMATCH | 前置列与基线列不一致 | 脱敏工具已保证同值替换不应出现；出现即查工具运行日志 |

- 预检**不写业务表**（只写 imp_job / imp_row / imp_issue，tech-plan §12④）；确认提交、分批写入与回滚属 E23-T06 / T07 / T11。

## 7. 迭代循环与完成定义

1. 医院 V1 样本 → §5 脱敏 → 上传预检 → 报告（§6）；
2. 有 ERROR：按 §6 处置（医院重出 / 配病区别名 / 修字典），**同一文件名可重复演练**（作业独立，历史作业保留比对）；
3. errorCount = 0：本任务验收达成；警告清单交产品与医院逐条确认（Q36 补录量、Q37 备注量、软范围条数——样本阶段的复核工作量估计，供 W34–W35 排期）；
4. 产出物归档（仓库外，与样本同密级）：脱敏样本、每次预检的批注版报告、复核清单结论；映射表按 §4 销毁或封存；
5. 衔接：E23-T06 用同链路做约 5000 名患者的导入演练（抽样核对 + 汇总数核对），E23-T07 记录演练耗时与回滚方案，E23-T11 正式导入。

## 9. 常见问题

- **输入文件在仓库内被拒绝**：护栏（§4 红线），把文件移到仓库外再跑。
- **工具报「宽表表头不匹配」**：文件不是 A 宽表（导出口径 §3）；差异清单带列字母，对照医院样例逐列核对。
- **预检大量 TYPE 错误且集中在日期列**：医院导出的是 Excel 日期序列号（数值单元格），让医院改为文本导出（§3）。
- **同一患者多行**：文件内病案号重复是警告（确认时按重复策略处理）；脱敏工具保持同一原值 → 同一虚构病案号，重复关系不变。
- **想复现上次映射**：用上次打印的 salt（stderr）重跑同一输入；映射表是权威记录。
