# 医院 A 导入演练 · 数据核对手册（W34–W35）

> 任务 E23-T06（测试，3 人天，依赖 E23-T05；验收：**抽样核对与汇总数核对一致**）。
> 需求依据：`docs/requirements/hospital-a-spec.md` A-PAT-018（宽表历史数据导入）§4「宽表历史数据导入流程」与「校验报告中的常见问题」（Q36 / Q37 已确认口径）、A-NFR-001（约 5000 名历史患者，医院已确认）。
> 按 `AGENTS.md` 第 9 节：「测试」任务交付自动化用例——仓库内常跑的是 **`ImportRehearsalVerifyIT`**（门控 `CRDP_IT_MYSQL_PORT`，CI 覆盖，门控与 `ImportScale5000IT` 同款），本手册是它在测试环境的人工对照版，也是 UAT J-2（`docs/testing/uat-hospital-a.md` §5 J 组）的执行依据。
> 衔接：E23-T05（样本脱敏，本演练的输入）、E23-T07（技术执行与问题修复：**耗时记录与回滚演练**，见 `docs/ops/hospital-a-import-rollback.md`，不在本手册）、E23-T11（正式导入与上线切换，W36，见 `docs/ops/hospital-a-go-live.md`）。

## 1. 目标与验收口径

- 目的：把「校验通过」的脱敏样本（E23-T05 判据：PRECHECKED 且 errorCount = 0）在**测试环境**真正**确认提交**一次（约 5000 名患者量级），然后做两种核对，两种都一致才算验收达成：
  - **汇总数核对**：源表（脱敏样本 / 演练宽表）的行数与年度分布 = 导入向导结果页的作业统计 = 库内各业务表计数 = 患者列表页筛选后的患者数 / 任务数（四路一致）；
  - **抽样核对**：从源表抽样（随机 20 名 + 批次边界 + 脏值行），逐字段比对该患者从源表行到库内的每一次转换（标识列、实体列、分节 JSON、联系方式、年度记录）。
- 为什么两种都要：汇总数一致只能证明「没丢行、没多行」；抽样一致才能证明「单元格级的转换与落库正确」（日期 `yyyymmdd` 转换、N/A 归空、Q36 按空值导入、Q37 取编码 + 文字进备注、原系统编号保留、病区映射、随访年度排期）。
- 演练数据红线：测试环境一律用**脱敏样本**（E23-T05 链路）或**全虚构演练宽表**（自动化用例生成，姓名 / 电话带「示例 / 演练」标记与 `IT-` 前缀，AGENTS §5.5）；真实患者数据不进任何仓库与 CI。

## 2. 链路总览

```
脱敏样本 / 虚构演练宽表（约 5000 行 × 761 列，测试环境）
  → 导入向导上传 + 预检（E23-T05 已验收：PRECHECKED、errorCount = 0；警告 = 人工复核清单）
  → 确认提交（重复策略 UPDATE；分批写入 200 名/批 × 25 批，E18-T05）
  → 作业 DONE（结果页统计 = 第一路汇总）
  → 数据核对（本手册 §3 汇总数核对 + §4 抽样核对）
  → 演练结束：按批回滚或整作业回滚清场（回滚方案、耗时记录与取证 SQL 见 docs/ops/hospital-a-import-rollback.md，E23-T07）
```

## 3. 汇总数核对（四路一致）

> 自动化对照：`ImportRehearsalVerifyIT#verifyBySummary`。人工执行时向导结果页 + 患者列表页即可完成 ①③ 两路；②④ 需要测试同学带只读 SQL（或请开发代查）。

| # | 口径 | 源表基准（怎么算） | 核对点 |
|---|---|---|---|
| ① | 作业统计（向导结果页「导入完成」） | 源表行数（每行一名患者，病案号唯一） | 新建患者数 = 源表行数；更新 / 跳过 = 0；年度记录数 = ③ 公式；批次 25 全 DONE、无失败批次 |
| ② | 库内计数（只读 SQL，按演练标记圈定队列） | 同上 | `pt_patient`（演练队列）= 源表行数；`fu_record` 按来源分计数（见下）；`fu_enrollment` = 行数（auto_enroll 预置计划）；`pt_contact` 按槽位 = 有电话1 / 电话2 的行数；`pt_baseline_section` = 每行实际落节数 × 行数 |
| ③ | 年度记录分布 | **每名患者**：有数据的年度 → HIST_IMPORT（SUBMITTED，实际随访日期）；出院/起算日期满 N 年的**窗口已结束**且该年度无数据 → HIST_MISSED（DRAFT，Q06）；窗口未结束的年度不生成 | 按年度逐个数：HIST_IMPORT 第 n 年 = 源表第 n 组非空的患者数；HIST_MISSED = Σ（已结束窗口数 − 有数据年度数）；第 4 年起（窗口开启中）无记录 |
| ④ | 任务数 | 历史导入**只入组不建任务**（A-PAT-018 流程 6：当前窗口的当年任务由每日定时任务创建） | 演练队列 `fu_task` = 0 |
| ⑤ | 患者列表页（用户看到的口径） | 按演练队列的病区 + 出院日期筛选 | 各病区患者数、合计患者数 = 源表同口径行数（UAT J-2「比对患者数 / 任务数汇总」） |
| ⑥ | 预检警告清单（人工复核清单的输入） | 源表脏单元格数：是否类填「0/1」的格数（Q36）、「编码+文字」的格数（Q37） | 校验报告里 BOOLEAN_01 / OPTION_CODE_TEXT 的条数分别 = 源表对应脏格数（不多报、不漏报，补录量估计才准） |

一致判据：①—⑥ 全部与源表基准相等；任何一路不等 → 按 §5 处置，修复后**重新演练**（可多次重新导入，A-PAT-018）。

## 4. 抽样核对（源表行 ↔ 库内患者逐字段）

> 自动化对照：`ImportRehearsalVerifyIT#verifyBySample`（固定种子随机 20 名 + 批次边界行 1 / 200 / 201 / 2500 / 4800 / 4801 / 5000 + 脏值首行）。

抽样建议（UAT J-2）：随机抽 20 名（记录抽样方法与种子 / 行号，可复现），**必须额外覆盖**：每批首尾行（200 名一批）、含 Q36 脏值的行、含 Q37 脏值的行、有电话2 的行、只有 1 个数据年度的行。

每名患者核对清单（源表行 ↔ 库内患者档案）：

| 类别 | 字段 / 对象 | 核对点（转换规则） |
|---|---|---|
| 检索入口 | 病案号 | 列表页按病案号精确检索**唯一命中**该患者（盲索引） |
| 标识列 | 病案号 / 姓名 | 明文值逐字段一致（需明文权限 + 二次确认；自动化用例走密文解密比对） |
| 原系统编号 | 前置列「患者编号」 | 原样保留在患者档案，仅用于追溯（A-PAT-018「保留原系统编号」） |
| 实体列 | 性别 / 病区 / 手术日期 / 入院日期 / 出院日期 | 显示名 → 编码（男 → M）；病区名 → 病区字典映射；`yyyymmdd` → 日期；出院日期为起算日期快照 |
| 基线 JSON | 诊断信息 / 手术备注 / 身高cm / ccs 分级等 | 分节存储的表单值逐字段一致；数值文本 → 数值；**Q37**：「2二级」→ 值 = 2、文字「二级」存该字段备注（data_meta）；**N/A** → 空 |
| 联系方式 | 电话1 / 电话2 | 有值才生成版本；解密值一致；来源 = 历史导入；每槽位恰一版 |
| 年度记录 | 每个年度一条 | 有数据年度：来源 HIST_IMPORT、状态已提交、实际随访日期 = 源表第 n 组随访日期（不受 ±7 天窗口限制，标「历史导入」）、表单值逐字段一致（随访日期 / 是否死亡 / EF 等）；**Q36**：是否类「1」→ 该字段**为空**（待人工补录）；无数据且窗口已结束：HIST_MISSED 草稿；窗口未结束：无记录 |
| 汇总补漏 | 完整度 | 基线资料 / 随访资料完整度由系统**重算**（原表「数据完整度」列不导入，A-PAT-019）——只验证有值（> 0 口径见 A-DASH-010/011），不与原表数字比对 |

一致判据：抽样患者**全部字段**一致；任何一名不一致 → 记缺陷（含行号、字段、源值 / 库内值对照），按 §5 处置。

## 5. 差异处置（发现不一致时）

| 现象 | 先查 | 处置 |
|---|---|---|
| 汇总数少行 | 向导批次页有无 FAILED / 跳过行明细（病案号为空 / 病区未映射 / 越范围） | 失败批次「重试」（PARTIAL_FAILED → IMPORTING，只重跑失败批）；跳过行修正源表或病区别名后重新演练 |
| 汇总数多行 | 演练队列标记外的患者混入（筛选条件） | 收紧核对口径（演练队列按标记 / 病区 + 出院日期圈定），不属导入缺陷 |
| 个别字段不一致 | 批注版校验报告该单元格（是否在警告清单：Q36 按空值、Q37 取编码、软范围、前置列与基线列不一致以基线列为准） | 报告已列的按已确认口径人工复核 / 补录；报告没列的 → 缺陷，开发定位（转换规则见 `ImportCellValidator` / `ImportCommitService`） |
| 年度记录错位（年份 / 日期对不上） | 宽表分组列位（第 n 组 = 第 n 年）、全空组是否被跳过 | 列位错 → 缺陷；源表组序异常 → 修正源表 |
| 想整批重来 | —— | 整作业回滚（写入逆序删除，「等于没导过」，E18-T05）后重新上传演练；**回滚路径决策、耗时记录与取证 SQL 见 `docs/ops/hospital-a-import-rollback.md`（E23-T07）** |

## 6. 自动化用例（仓库内常跑）

- `backend/crdp-server/src/test/java/com/crdp/server/followup/ImportRehearsalVerifyIT.java`：5000 行 × 761 列全虚构宽表（生成时同步记**台账**），走导入向导同一 HTTP 链路上传 → 预检 0 错误 → 确认提交 DONE，然后按本手册 §3 / §4 的口径机判：
  - 汇总数：台账 = 作业 stats = 库内（患者 / 按年度按来源的记录 / 入组 / 联系方式 / 分节 / 任务 = 0）= 列表 API（按病区 + 出院日期）；预检警告 BOOLEAN_01 / OPTION_CODE_TEXT 计数 = 台账脏格数；
  - 抽样：固定种子随机 20 + 批次边界 + 脏值行，逐字段核对（含解密比对、Q36 空值、Q37 编码 + 备注、Q06 历史未随访草稿、窗口未结束不生成）。
- 运行：`CRDP_IT_MYSQL_PORT=13306 mvn -B -f backend/pom.xml -pl crdp-server test -Dtest=ImportRehearsalVerifyIT`（CI 全量恒跑）。与 `ImportScale5000IT`（E18-T07：规模 + 回滚）互补，本用例只管数据核对、不做回滚。
