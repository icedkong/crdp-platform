# 医院 C 报告单类型与程控报告单映射配置与激活 runbook（W41 · E23-T21）

> 任务 E23-T21（产品 · 产品，2 人天，依赖 **E23-T20** C 的字段字典与两套计划；验收：**程控报告单可映射字段**）。
> 需求依据：`docs/requirements/hospital-c-spec.md` §6「报告单与纸质资料归档」——C-SCAN-002（资料类型与按类型表单）、C-SCAN-003（名称字典、检查 / 检验类必填）、C-SCAN-004（指标模板，凝血四项示例）、C-SCAN-005（程控报告单映射程控字段）、C-SCAN-011（默认电子化状态）。
> 按 `AGENTS.md` 第 9 节：生产侧的激活操作（启用 C 类型、停用 A 类型、与医院 C 核对名称字典）由实施 / 租户管理员在场完成，本 runbook 是他们照着走的**配置手册**；仓库交付预置迁移（followup V94）与行级核对（`CReportPresetSqlTest`，CI 恒跑）。
> 衔接：E23-T20（97 个字段与两套计划）→ **E23-T21（本任务：报告单 10 类 + 程控映射）** → E23-T22（科室、病区、用户与角色）、E23-T23（C UAT 组织与问题跟踪）。

## 1. 目标与验收口径

- 医院 C 使用本院预置 10 类资料类型（C 规格 §6「预置资料类型」表）与程控报告单 → 随访程控记录的字段映射：

| 类型 | 编码 | 处置 | 名称必填（C-SCAN-003） | 默认电子化状态（C-SCAN-011） |
|---|---|---|---|---|
| 程控报告单 | `C_PROGRAM` | 本院预置（V94，随包停用） | 否 | 待录入 PENDING |
| 纸质随访表 | `C_PAPER_FORM` | 本院预置（V94，随包停用） | 否 | 待录入 PENDING |
| 植入手术记录 | `C_IMPLANT_RECORD` | 本院预置（V94，随包停用） | 否 | 待录入 PENDING（「出院小结」「起搏器识别卡」两个名称覆盖为无需录入） |
| 心电图/动态心电图 | `C_ECG` | 本院预置（V94，随包停用） | 是 | 无需录入 NO_ENTRY |
| 胸片 | `C_CHEST` | 本院预置（V94，随包停用） | 是 | 无需录入 NO_ENTRY |
| 心脏超声 | `C_ECHO` | 本院预置（V94，随包停用） | 是 | 无需录入 NO_ENTRY |
| 检验 | `C_LAB` | 本院预置（V94，随包停用） | 是 | 无需录入 NO_ENTRY |
| 知情同意书 | `C_CONSENT` | 本院预置（V94，随包停用） | 否 | 无需录入 NO_ENTRY |
| 通话记录 | `CALL` | **复用 A 预置**（编码被前后端契约固定，见 §2） | 激活时调为否 | 激活时调为 NO_ENTRY |
| 其他 | `OTHER` | **复用 A 预置**（字段集时间 / 说明 / 附件与 C 一致） | 激活时调为否 | 激活时调为 NO_ENTRY |

- 程控报告单映射（C-SCAN-005，验收判据）：`C_PROGRAM_TO_FU`——「程控报告单指标」模板 21 项（电池 3、起搏阈值与脉宽 4、感知 2、阻抗 2、起搏比例 2、程控参数 4、ICD 项目 4，与 C 规格「程控报告单模板映射示例」表逐项一致）经 `rpt_mapping` 一一对应 `C_PROGRAM_FU` 字段（V90 键位契约 f322 电池电压、f323 ERI 状态〔`c_eri_status` 0-1-2〕、f318 程控起搏模式〔统一起搏模式字典〕、f329 / f330 ICD 恰当 / 不恰当治疗〔多选〕…）；目标 = 报告单位置中的随访记录（整条或程控分组，多条选一条），写入走 E16-T07 预览 / 确认（报告单不另存一份参数）。值转换（含多选 → 编码数组）随 E23-T21 开放（`MappingValues`）。
- 无 `REPORT_DATE` 映射行：随访日期 `f303` 由转录 / 补录流程落（OQ-131②——位置中无随访记录时只存附件，「选择或新建补录记录」发生在转录流程 C-SCAN-012 / E21-T17），映射不写该字段。
- 验收判据（对应 C 规格验收「选择类型程控报告单、位置选第 N 次随访，录入的电池电压与心室起搏阈值出现在第 N 次随访记录中，报告单变为已电子化」）：
  1. **预置行随包且与规格逐项一致**：followup V94 进入所有租户库；行级参数由 `CReportPresetSqlTest`（CI 恒跑，8 例）锁定，映射目标字段键与 V90 字段字典交叉核对（无悬空引用）；落库后同一口径由 `ReportConfigIT`（MySQL 门控）经 HTTP 再核（类型停用可见、映射 21 项可读）；
  2. **程控报告单可映射字段**：C 激活后，程控报告单（名称绑定「程控报告单指标」模板带出 21 个项目）转录时预览列出将写入的程控字段（原值 / 新值 / 冲突），确认写入目标随访记录、报告单转已电子化；
  3. **C 侧激活**：8 类启用 + A 类型停用 + CALL / OTHER 差异调整，由本手册 §3 完成。

## 2. 载体与状态（为什么随包是停用的）

- 报告单类型是租户库数据（`rpt_type`），随包进**所有**租户库（V38 / V61 / V62 同口径，`AGENTS.md` §5.7 不写租户分支）。C 的 8 类若随包启用，医院 A / B 添加报告单的类型下拉会立刻出现「程控报告单」「纸质随访表」等本院没有的类型——因此：
  - V94 以 **DISABLED** 落库：对 A / B **惰性**（添加报告单不可选、运行时目录 `report-types` 只吐 ENABLED、配置页可见但灰），医院 C 侧启用后即生效（OQ-142①；与 V91 计划 UNPUBLISHED 草稿同「随包惰性 + 院内激活」口径，OQ-128②）；
  - 名称与指标模板随包 ENABLED：只经所属类型露出，类型停用即不可达，无需单独激活；
  - 映射 `C_PROGRAM_TO_FU` 随包 ENABLED：映射按报告单类型触发，类型停用下不存在 `C_PROGRAM` 报告单，对 A / B 天然惰性；C 启用类型即生效，无需再激活映射。
- **「通话记录」「其他」复用 A 预置 CALL / OTHER，不另建 C 行**：CALL 编码被契约固定（后端 `CallReportService.CALL_TYPE_CODE = "CALL"` 沟通记录联动〔录音同源、位置预选、连带删除〕，前端 `report-dialog-logic.ts` 的 `CALL_TYPE_CODE` 与通话时间 / 说明槽位编码）；RPT_CALL 字段集（通话时间、通话说明、音频 m4a / mp3）与 C 规格「通话记录」主要字段一致；RPT_OTHER（时间、说明、附件）同理。C 差异（名称选填、默认无需录入、名称字典「随访电话 / 失访追踪」）是**共享行上的库内数据动作**，随 §3 调整——不进迁移，避免随包改动 A / B 的行为（OQ-142②）。
- **时序约束（与 B 激活同款，OQ-128②）**：激活必须在配置模板应用（开通向导）之后——六张报告单配置表在配置模板注册表内（E12），模板按自然键 upsert 会回写这些行；重导模板后须重做 §3。
- 已知衔接：A 预置的 10 个 REPORT 表单未建 `fe_form_version` 快照（V62 既有口径，A 类型字段集从未经写入闸门提交）；C 的 8 个表单随 V94 建 v1 快照（类型字段写入走 `writeGateData` 按版本取字段，与 V90 同款）。

## 3. 激活执行（C 租户管理员 / 实施，开通核对通过后）

前置：E23-T22 的科室、病区、用户与角色配置完成；`followup` 模块与 `followup:scan:config`（报告单设置菜单 39）、`followup:scan:upload` 等权限已授予。顺序约束见 §2 末条。统一入口：医院端 → 系统设置 → 报告单设置（`/api/hospital/followup/report-config/**`，全部写 `RPT_*` 审计）。

| # | 步骤 | 入口（UI / API 等价） | 判据 |
|---|---|---|---|
| 1 | 启用 C 的 8 类预置 | 报告单设置 → 类型列表 → `C_PROGRAM` / `C_PAPER_FORM` / `C_IMPLANT_RECORD` / `C_ECG` / `C_CHEST` / `C_ECHO` / `C_LAB` / `C_CONSENT` 逐个编辑启用（`PUT /report-config/types/{id}`，`status: "ENABLED"`）；可同时按本院习惯调 `sortNo`（随包 110–180 接在 A 之后） | 添加报告单对话框可选 10 类（8 新 + CALL + OTHER）；运行时目录 `GET /report-types` 含 C 类型与各自字段集 |
| 2 | 停用 A 的 8 类预置 | 同上，把 `ECHO` / `ANGIO` / `ECG` / `CHEST_IMAGING` / `LAB` / `DISCHARGE_SUMMARY` / `OPERATION_RECORD` / `CONSENT` 逐个停用（`status: "DISABLED"`；**保留 CALL 与 OTHER**） | 添加报告单不再出现 A 专属类型；已存在的 A 类型报告单不受影响（停用不删数据） |
| 3 | CALL / OTHER 差异调整（共享行） | CALL 与 OTHER 编辑：`nameRequired: false`、`defaultDigitizeStatus: "NO_ENTRY"`（C-SCAN-003 / 011）；CALL 名称字典补「随访电话」「失访追踪」（`POST /report-config/names`，绑不绑模板均可；A 预置「随访电话录音」可停用或保留） | 通话记录 / 其他名称选填、默认无需录入；沟通记录上传录音联动 CALL 报告单不受影响（编码未动） |
| 4 | 核对名称字典与指标模板 | 名称字典按 C 规格「名称字典示例」列逐项核对（程控报告单 3、纸质随访表 2、植入手术记录 3〔出院小结 / 识别卡无需录入〕、心电图 2、胸片 2、心脏超声 1、检验 6〔凝血四项绑模板〕、知情同意书 2）；凝血四项模板按本院检验科补参考范围（`PUT /indicator-templates/{id}`） | 选检验 → 凝血四项自动带出 PT、PT%、INR、APTT、TT、Fbg 六行及代码、单位、参考范围 |
| 5 | 程控映射验证（验收判据） | 给虚构患者（示例）建一条随访程控记录并添加程控报告单（名称「常规程控」带出 21 个项目、位置选该随访记录），填电池电压 / 心室起搏阈值 / ERI 状态 / ICD 项目后保存 → 报告单详情「转录到结构化记录」预览 → 确认 | 预览列出将写入的程控字段（原值 / 新值 / 冲突）；确认后参数出现在该随访记录（报告单不另存一份）、报告单转「已电子化」；ERI 状态写「接近ERI」后该患者转 ERI 期随访（E21-T06） |

> 步骤 1 / 2 / 3 也可以合并为一次库内数据动作由实施在开通编排后执行（全部经配置接口或 SQL UPDATE，均写审计或留运维留痕）；重导配置模板后须重做本节（§2 时序约束）。

## 4. 行级核对与防漂移

- `CReportPresetSqlTest`（CI 恒跑，8 例）：8 类类型行（编码 / 名称 / 字段集 / 名称必填 / 默认电子化状态 / 排序 / 随包停用）、CALL / OTHER 复用不重复插入、每类 REPORT 表单与主要字段（含检查所见 / 诊断槽位编码）、v1 版本快照、名称字典 21 行与模板绑定 / 无需录入覆盖、凝血四项 6 项（名称 / 代码 / 单位）、映射头与 21 个映射项（映射示例表逐项、无 REPORT_DATE 行、目标字段键与 V90 交叉核对、目标字段类型与单位兼容）。
- `ReportConfigIT`（MySQL 门控，CI 带 `CRDP_IT_MYSQL_PORT` 运行）：配置接口可见 C 类型（停用、名称选填、PENDING）与 `C_PROGRAM_TO_FU` 映射（21 项、目标 `C_PROGRAM_FU`、电池电压 → f322、ICD 恰当治疗 → f329）；A 生效类型仍为 10 类、双租户隔离不受影响。
- `MappingValuesTest`：多选转换（顿号 / 逗号 / 分号分隔的选项名或编码 → 编码数组、去重保序、非法项报错）与字典绑定单选（字符串编码原样可写）。
- 改 C 规格附录或映射示例后：改 V94 不行（Flyway 只新增）——以新迁移或配置接口调整，并同步本手册与 `CReportPresetSqlTest` 的锁定口径。
