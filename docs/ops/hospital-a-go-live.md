## 1. 目标与验收口径

- 把医院 A 的**正式历史数据**（约 5000 名患者，宽表版面与演练样本同构）在生产租户库导入一次（预检 0 错误 → 确认提交 DONE），完成两种核对（汇总数 + 抽样，口径 = `docs/ops/hospital-a-import-rehearsal.md` §3 / §4），全部一致后执行上线切换（入口开放 + 租户转正），医院 A 用户开始正式使用。
- 验收判据「生产导入核对通过，A 上线」拆成三件可判定的证据：
  1. **核对通过**：§5.2 机器侧核对工具输出全部 PASS（台账 ↔ 库内一致）**且** §5.3 抽样核对（人工，含明文字段）逐字段一致；
  2. **切换完成**：§6 切换动作清单全部勾选（DNS → WAF CNAME、租户转正 ENABLED、观察期监控无阻断性告警）；
  3. **留痕**：§5.4 核对记录与 §8 切换留痕归档运维 wiki（仓库不留生产数据，AGENTS §5.5：真实患者姓名 / 电话 / 病案号**不进仓库、不进 CI、不进日志**）。

## 3. 上线窗口与耗时预算

- 排期：**W36（2027-07-19 当周）**，选医院低峰窗口（建议周末上午）；参加人员：运维（持云账号）、全栈 1（本任务）、实施 / 产品（医院在场）、测试（衔接 E23-T12）。
- 耗时预算按 E23-T07 §7 **实测**推算（5000 行 × 761 列，本机 MySQL；生产 RDS 性能更高，预算留裕量）：

| 阶段 | 演练实测 | 生产预算（含人工复核） |
|---|---|---|
| 上传 + 预检 | 4.2 s（PRECHECKED、0 错误） | ≤ 15 分钟（含上传带宽与预检等待） |
| 警告人工复核（Q36 / Q37 清单） | ——（演练为虚构脏格） | 30–60 分钟（E23-T05 口径的复核清单，正式数据脏格数以预检报告为准） |
| 确认提交（25 批 × 200 名） | 51.2 s（15,000 条年度记录） | ≤ 10 分钟 |
| 汇总数核对（机器侧 §5.2） | 秒级（只读 SQL） | ≤ 15 分钟（含台账登记） |
| 抽样核对（人工 §5.3） | —— | 60–120 分钟（20 名随机 + 边界行逐字段，含明文二次确认操作） |
| 切换动作（§6） | —— | ≤ 30 分钟（DNS 生效等待为大头） |
| 冒烟（E23-T12 衔接） | —— | 60 分钟 |

- 时间线纪律：**核对未全部通过不切换**；窗口超时（如人工复核远超预算）→ 顺延，不半上线；确认提交后的导入可多次重来（A-PAT-018 流程 5），回滚耗时预算见 `docs/ops/hospital-a-import-rollback.md` §7（整作业回滚 20.3 s 实测，生产按 ≤ 5 分钟预算）。

## 4. 正式数据交接（生产口径）

1. 医院按 `docs/ops/hospital-a-sample-intake.md` §4 的交接流程交付**正式宽表**（约 5000 行 × 761 列）：交接单记录文件名、行数、SHA-256、交付人 / 接收人；
2. 与演练样本做**版面一致性**抽查（列数、列头、分组列位与 E23-T05 确认的版面一致）——版面漂移会让预检直接失败，属 G7 未达成；
3. 正式文件只进生产环境与交接双方的受控存储；**不进仓库、不进 CI、不进测试环境**（演练用脱敏样本已覆盖测试环境）；
4. 交接后即登记 §5.2 台账（源表基准）：行数、按病区分布、年度分布、电话 1/2 行数、分节数、Q36 / Q37 脏格数（从预检报告回填或源表统计）。

## 5. 生产导入执行与核对

### 5.1 执行步骤（导入向导，与演练同链路）

| # | 步骤 | 入口 | 判据 |
|---|---|---|---|
| 1 | 上传正式文件 | 医院端 → 随访 → 历史数据导入（`wide_import` 开关租户已开） | 作业 UPLOADED；同一时间仅一个作业（进行中再传 40901） |
| 2 | 预检 | 向导自动 | `PRECHECKED` 且 **errorCount = 0**；警告清单 = Q36 / Q37 人工复核清单 |
| 3 | 警告人工复核 | 校验报告（批注版） | 逐条结论（按空值导入 / 取编码进备注），登记复核清单 |
| 4 | 确认提交 | 向导「确认提交」，重复策略 UPDATE | 作业 DONE、25 批全部 DONE、无失败批次（有失败 → `docs/ops/hospital-a-import-rollback.md` §1 决策树路径 5 重试） |
| 5 | 汇总数核对 | §5.2 工具 + 向导结果页 | 全部 PASS |
| 6 | 抽样核对 | §5.3 人工 | 全部一致 |

### 5.2 汇总数核对（机器侧工具，只读）

工具：`scripts/golive_import_verify.py`（本任务交付）。生产执行（持账号运维，从运维主机）：

```bash
export CRDP_GOLIVE_MYSQL_PASSWORD='<只读账号口令>'   # 只进 mysql 客户端进程环境，不进 argv、不落盘
python3 scripts/golive_import_verify.py \
  --host <生产 RDS 地址> --port 3306 --db t_<租户编码> --user <只读账号> \
  --job <导入作业 imp_job id> --ledger <台账.json>
```

- 账号用**只读**账号（生产 RDS 最小权限，`iac/rds-prod` 口径）；工具内置只读护栏，任何非 SELECT 语句直接拒绝；
- 核对项（口径 = `docs/ops/hospital-a-import-rehearsal.md` §3）：作业终态 DONE 与暂存行数、批次统计（新建+更新+跳过 = 源表行数）、患者主档数、年度记录按年分布（HIST_IMPORT / HIST_MISSED）、入组数、电话 1/2 联系方式版本数、基线分节数、**任务 = 0**（A-PAT-018 流程 6 导入不建任务）、Q36 / Q37 警告数与预检错误 = 0、上传 / 提交审计恰各 1 条、批次写数清单 PATIENT 行 = 新建数（回滚反查依据）、病区分布；
- 台账 `--ledger`（源表基准，交接后登记）必填键：

```json
{
  "marker": "<队列标记：正式导入以原系统编号前缀圈定>",
  "jobId": 0,
  "patients": 0,
  "batches": 0,
  "wardCounts": {"<病区id>": 0},
  "histImportByYear": {"1": 0, "2": 0, "3": 0},
  "histMissed": 0,
  "phone1": 0,
  "phone2": 0,
  "sections": 0,
  "warnBoolean01": 0,
  "warnOptionCodeText": 0
}
```

  可选键 `updatedPatients` / `skippedPatients`（默认 0；重导后走更新路径时按实填）。`marker` 白名单 3~32 位字母数字与 `-_`，防注入；工具 `--selftest` 内置台账与护栏自检；
- 任何一项 FAIL → 停，按 §7 处置；全部 PASS 才进 §5.3。

### 5.3 抽样核对（人工，含明文）

口径 = `docs/ops/hospital-a-import-rehearsal.md` §4：固定记录种子 / 行号的**随机 20 名 + 批次边界行（1 / 200 / 201 / 2500 / 4800 / 4801 / 5000）+ 含 Q36 / Q37 脏值的行 + 有电话 2 的行 + 只有 1 个数据年度的行**。每名患者逐字段核对：病案号检索唯一命中、标识列（病案号 / 姓名需**明文**权限 + **二次确认**，60 秒自动恢复脱敏）、原系统编号保留、实体列（性别 / 病区 / 三个日期）、基线分节 JSON、联系方式解密值、年度记录（来源 / 状态 / 实际随访日期 / 表单值；Q36 待补录字段为空、Q37 编码 + 文字进备注）。任何一名不一致 → 记缺陷，按 §7 处置。

### 5.4 核对记录（归档，不进仓库）

| 项 | 值 |
|---|---|
| 日期 / 执行人 / 复核人 / 导入作业 id / 文件 SHA-256 | |
| 台账登记（行数 / 病区分布 / 年度分布 / 脏格数） | |
| §5.2 工具输出（逐项 PASS/FAIL） | |
| 抽样清单（种子 / 行号）与逐字段结论 | |
| 差异与处置（缺陷号 / 回滚路径 / 重导作业 id） | |
| 结论（是否放行 §6 切换） | |

## 7. 中止与回滚

- **切换前（核对不一致）**：按 `docs/ops/hospital-a-import-rollback.md` §1 回滚决策树选路——个别批次错 → 按批回滚；口径不一致或源表要改 → 整作业回滚「等于没导过」后修正重导（可多次）；越出导入链路 → `docs/ops/tenant-restore.md` 单院恢复（灾难恢复预案）。回滚全程审计只追加；
- **切换前（窗口超时）**：作业保持 DONE 不动（数据已核对一致）或整作业回滚重来，顺延窗口；不带「核对一半」的状态进切换；
- **切换后（发现阻断问题）**：入口回切（DNS 摘除 WAF CNAME）停止用户访问 → 缺陷修复与验证 → 重新开放；**已导入数据不回滚**（生产已有真实使用痕迹时回滚删除不可逆，任何数据修复走字段历史与缺陷流程）；极端情况（数据损坏）走 `docs/ops/tenant-restore.md` 时间点恢复，须先停止写入并通报医院方；
- 每次中止 / 回滚记入 §5.4 记录与上线评审材料。

## 10. 自动化对照（CI 恒跑）与演练

`scripts/golive_import_verify.py`（本任务）在 CI 与本机按三种模式运行（`.github/workflows/ci.yml`）：

```bash
python3 scripts/golive_import_verify.py --selftest   # 纯逻辑自检：台账校验 / 只读护栏 / 夹具自洽
python3 scripts/golive_import_verify.py              # 本 runbook 防漂移校验（闸门 / 口径 / 接线）
python3 scripts/golive_import_verify.py --drill      # compose MySQL：虚构终态全 PASS + 四类差异逐项检出 + 清场归零
```

- `--drill` 在 compose MySQL 演示租户库 `t_demoa`（真实 Flyway schema）造 60 名虚构患者（标记 `GLVDRL-`，AGENTS §5.5）的「导入 DONE」终态，跑生产同款核对全部 PASS；随后注入**少一名患者 / 年度记录多 2 条 / 误建随访任务 / 缺提交审计**四类差异，逐项检出 FAIL；结束清理归零（审计行经 `@crdp_audit_maintenance` 维护逃生口删除，与后端测试自清理同口径）；
- 防漂移校验锁定：验收原句与依赖、闸门引用的既有文档存在且被引用、转正 API（PLT-TEN-010）、DNS → WAF CNAME 口径、台账必填键与脚本一致、ci.yml 接线、`docs/README.md` 索引；
- 生产核对（`--host ... --ledger ...`）不在 CI 运行，由持账号运维按 §5.2 执行。
