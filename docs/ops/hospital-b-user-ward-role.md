# 医院 B 用户、病区与角色配置 runbook（W38 · E23-T18）

> 任务 E23-T18（产品 · 产品，1 人天，依赖 **E23-T15** B 租户开通；验收：**B 用户按病区分配**）。
> 需求依据：`docs/requirements/hospital-a-spec.md` 第 14 章「医院 B 配置差异」——「用户、角色取值」：用户账号不复制，B 约 30 名用户按病区分配；「术者、病区 / 中心」：只复制结构、不复制取值，由 B 租户管理员自行维护；未列出的内容沿用第 1–13 章：§6 病区与数据隔离（A-WARD-001/002/003/004/007）、§10 建议角色模板（病区范围与主要权限矩阵）。
> 按 `AGENTS.md` 第 9 节：生产侧的用户 / 病区 / 角色录入（按交接单）由 B 租户管理员 / 实施在场完成，本 runbook 是他们照着走的**配置手册**；仓库交付预置种子（tenant/seed V136，local / dev / IT 演示与核对用）、行级核对（`BPresetWardUserSqlTest`，CI 恒跑）与落库演练 IT（`BPresetWardUserVerifyIT`，门控 CRDP_IT_MYSQL_PORT，demob 作 B 化身）。
> 衔接：E23-T15（B 租户开通）→ E23-T16（B 预置计划激活）→ **E23-T18（本任务）** → E23-T17（B 验收）、E23-T28（B 回归：A 不受影响）、E23-T19（B 上线切换，runbook `docs/ops/hospital-b-go-live.md`）。与 E23-T16 无先后依赖（用户配置不触碰计划行），但建议在 §4 抽查前完成计划激活，使登记虚构患者即产生 B 预置任务。

## 1. 目标与验收口径

- 医院 B 的病区 / 中心字典、业务角色（含病区范围）与约 30 名用户按病区分配配齐：医生只能看到负责病区的数据（A-WARD-004），一个医生可负责多个病区（A-WARD-002），科主任 / 项目负责人全院可见（A-WARD-003），每个病区有默认随访负责人（A-WARD-001 / A-FU-009）。
- 验收判据「B 用户按病区分配」拆成三件可判定的证据：
  1. **预置行随包且与规格逐项一致**：tenant/seed V136 进入演示 / IT 的每个租户库（OQ-93 ①/② 口径），行级参数由 `BPresetWardUserSqlTest`（CI 恒跑）锁定——角色矩阵 16 病区医生 / 8 随访员 / 4 科主任·项目负责人 / 2 数据录入员、病区字典 3 病区 + 2 中心、敏感项（211 明文 / 212 导出 / 217 删除）不预授；
  2. **按病区分配的行为**：B 病区医生检索只见本病区患者、直接访问他病区患者 40400、跨病区医生见并集、科主任全院可见——由 `BPresetWardUserVerifyIT`（demob 化身，门控）走通，另核权限预览可见病区与来源角色（A-WARD-009）；
  3. **生产录入路径**：B 租户管理员按交接单经病区 / 角色 / 用户页录入或批量导入（§3），抽查判据同 2。
- 生产库**不执行种子**（TenantSchemaMigrator 只在 local / dev / demo 剖面带 seed 目录）：真实身份不入库是红线（AGENTS §5.5），V136 的 30 名虚构账号不进生产 B 库，生产由 §3 录入真实用户。

## 2. 载体与口径（为什么放种子、为什么与 V123 并存）

- 用户账号与病区 / 中心取值是**租户自有序数据**：A-FLD-014 配置模板「不复制用户账号」「病区 / 中心字典只复制结构、不复制取值」（E23-T15 红线核对已锁），B 的取值只能由 B 侧自建——本任务交付的 V136 是该口径的**参考实现与演示数据**，与 A 预置 V123（E23-T04）同目录同构（OQ-93 ①）。
- 种子对每个租户库执行同一脚本（V100 / V123 同口径，OQ-93 ② / OQ-128 ③）：各演示租户库都带 A、B 两套预置，命名空间互不相交（`a.`/`b.` 账号、`W-A-`/`W-B-` 病区码、`A_`/`B_` 角色码），`BPresetWardUserSqlTest.coexistsWithAPresetInSharedSeedDatabases` 锁定不串。产品若后续要求「B 演示租户不带 A 预置」，按 OQ-93 ② 备选按租户停用，需租户身份进种子执行上下文，届时单开任务。
- B 业务角色复制自 §10 建议角色模板（PLT-ORG-005 模板角色不可直接分配；第 14 章角色模板与权限点随 A 模板复制，B 自有角色的增删属本任务）：名称与 A 同名（病区医生 / 随访员 / 科主任 / 数据录入员），角色码 B 前缀；菜单授予与数据范围按 §10 矩阵，敏感项不预授。
- 数据录入员的「导入」入口暂缺（E18 后补授）、「仅本人负责的患者」按需加选——两条均沿用 OQ-93 ②③ 口径，B 侧不另立。

## 3. 生产配置执行（B 租户管理员 / 实施，W38）

前置：E23-T15 两级核对通过（B 租户 TRIAL/ENABLED、角色模板与权限点已随模板落地）；交接单（医院 B 提供：病区 / 中心清单与别名、30 名用户的账号·姓名·工号·角色·负责病区、各病区默认随访负责人）已经医院 B 确认。真实姓名与工号只进 B 租户库，不进仓库、不进文档（AGENTS §5.5）。

| # | 步骤 | 入口（医院端） | 判据 |
|---|---|---|---|
| 1 | 录入病区 / 中心字典 | 系统管理 → 病区管理 → 新建（编码 / 名称 / 类型 / 别名 / 排序） | 编码本院唯一、创建后不可改（A-WARD-001）；历史写法进别名（A-WARD-006 值映射） |
| 2 | 建业务角色并配数据范围 | 系统管理 → 角色管理 → 从模板复制（病区医生 / 随访员 / 科主任 / 数据录入员）→ 数据范围 | 病区医生 / 随访员 / 录入员 = 本人负责病区，科主任 = 全部病区（A-WARD-003）；敏感项（明文 / 导出 / 删除）不预授，按需经平台放开后分配（§10） |
| 3 | 录入用户并分配角色 | 系统管理 → 用户管理 → 新建 / 批量导入（E06-T07 / E06-T08）→ 分配角色 | 约 30 名用户（交接单口径）；每人至少一个业务角色；首登改密策略按医院要求 |
| 4 | 按病区分配（验收主判据） | 用户管理 → 编辑 → 负责病区多选（A-WARD-002）；或病区管理 → 成员维护 | 每名医生 / 随访员 / 录入员勾选负责病区；跨病区医生多选；科主任不配清单（全院） |
| 5 | 配默认随访负责人 | 病区管理 → 各病区 / 中心 → 默认随访负责人 | 每个病区 / 中心都配，负责人是负责本病区的随访员（A-FU-009 兜底与逾期抄送按此解析） |
| 6 | 抽查 | 用交接单中的 1 名病区医生账号登录 | 患者列表只见本病区；直接访问他病区患者 40400；跨病区账号见并集（§6 验收）；抽查记录归档运维 wiki，不含患者数据 |

- 失败停留：某病区 / 用户与交接单不符 → 当场改配重查；角色误配敏感项 → 角色页移除（会话下次请求即失效，权限版本递增）。
- **A 不受影响**：本节全部动作只写 B 租户库。

## 4. 回滚与处置

- 用户配错病区：用户编辑页改选即生效（A-WARD-002 分配或取消立即生效，权限版本号递增）；范围为「本人负责病区」但未分配任何病区的用户看不到患者，页面提示联系管理员（§6 规则）。
- 人员离职 / 停用：用户停用（不删除，保留审计关联）；病区撤并：病区下仍有在随访患者时不能停用，须先转出（A-WARD-008，P1 首期口径）。
- 整批配错重来：批量导入的错行按导入校验报告修正后重导（E06-T08 幂等口径）；角色停用即从会话收回，不需要删角色。
- 中止上线：B 尚无正式患者数据时，用户 / 病区 / 角色配置可整租户重来（走 E05-T08 注销口径的成本评估，见 `hospital-b-onboarding.md` §7）。
