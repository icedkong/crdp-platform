## 1. 目标与验收口径

- 医院 C 使用两套本院预置计划（C-FU-002 / Q03 节点表，起算日 = **植入日期**）：

| 节点 | 计划日期 | 提醒提前量 | 窗口 | 适用 |
|---|---|---|---|---|
| 术后72小时/出院前 | 植入日期 +3 天 | 3 天 | 植入日至植入后 7 天（前 3 后 4） | 全部 |
| 术后1个月 | 植入日期 +1 个月 | 7 天 | 前后 7 天 | 全部 |
| 术后3个月 | 植入日期 +3 个月 | 14 天 | 前后 14 天 | 全部 |
| 术后6个月 | 植入日期 +6 个月 | 14 天 | 前后 14 天 | 全部 |
| 术后1年 | 植入日期 +12 个月 | 30 天 | 前后 30 天 | 全部（医院答复未单列，保留原默认〔假设〕，作为常规随访的第一次） |
| 常规随访（持续循环） | 上次实际随访日期 +12 个月（可设 6–12） | 30 天 | 前后 30 天 | 普通起搏器（`enroll_mode = NORMAL`） |
| 常规随访（持续循环） | 上次实际随访日期 +6 个月（可设 3–6） | 14 天 | 前后 14 天 | ICD、CRT-D（`enroll_mode = NORMAL`） |
| ERI期随访（持续循环） | 上次实际随访日期 +1 个月（可设 1–3） | 7 天 | 前后 7 天 | 标记接近 ERI 后至更换器械（`enroll_mode = ERI`） |

- 入组前已过窗口策略 = **SKIP**（Q14 / C-PAT-008：历史患者建档只为今天之后开始的窗口创建任务、之前的节点不算逾期——与 A / B 预置的 BACKFILL 相反）；任务 = 表单任务（C_PROGRAM_FU 随访程控记录表单，V90 字段字典随包）+ 责任医生。
- 验收判据：
  1. **预置行随包且与 Q03 节点表逐项一致**：followup V91（`C_PACER_FU_PLAN` / `C_ICD_FU_PLAN` v1）进入所有租户库；行级参数由 `CPresetPlanSqlTest`（CI 恒跑）锁定，含器械类型映射（V86）与排期示例（72 小时窗口、SKIP、enroll_mode 过滤）；
  2. **字段顺序与纸质表一致**（本任务验收原文）：`CFieldDictSqlTest`（CI 恒跑）锁定附录 A ↔ V90 逐项一致，患者登记 21 列与随访程控记录 34 列的 `sort_no` = 纸质表行号 × 10 严格递增；人工核对按附录 A 比对（纸质表不进仓库，CL-01：附录「类型、范围、必填为初步建议」逐项确认随 UAT / E23-T23）；
  3. **C 侧激活**：两套预置发布（保存植入记录后按 V86 映射自动入组、起算快照 = 植入日期），由本手册 §3 完成。

## 2. 载体与状态（为什么不直接随包发布）

- 预置计划与字段字典都属模块配置，随包进**所有**租户库（与 V38 / V61 / V80 同口径，`AGENTS.md` §5.7 不写租户分支）。若 V91 直接以 `PUBLISHED + auto_enroll = 1` 落库，医院 A / B 保存植入记录的租户若开启 impl 开关会同时自动入组 C 计划——因此：
  - V91 落库状态为 **UNPUBLISHED（未发布草稿）** + `auto_enroll = 1`（OQ-128②：C 预置同型复制 B 口径）：对医院 A / B **惰性**（impl 开关关闭不保存植入记录、映射行在族无已发布版本时跳过自动入组，OQ-135④；不进已发布计划候选与 node_rate 缺省计划），医院 C 侧发布后自动入组即生效；
  - 字段字典（V90）无需激活：表单模板按 code 读取，C 租户的录入页直接使用 `C_REGISTRATION` / `C_IMPLANT` / `C_PROGRAM_FU`；A / B 不引用这些 code 即不受影响。
- 已知衔接（OQ-139）：常规随访循环节点第 1 次回落起算日（植入日期 + 间隔）与「术后1年 / 术后6个月」固定节点计划日重合——滚动排期引擎（E21-T07）落地时须定义首次抑制（有已完成随访后从该次起滚动，否则跳过与固定节点重合的首次）；计划为未发布草稿，C 上线（E23-T23）前 E21-T07 已交付。

## 3. 激活执行（C 租户管理员 / 实施，开通核对通过后）

前置：E23-T22 的科室、病区、用户与角色配置完成；`implant`、`eri_cycle`、`record_edit_submitted` 等功能开关按 C 上线配置写入（OQ-71① / OQ-136①）。顺序约束与 B 同款：激活必须在配置模板应用（开通向导）之后进行；重导模板后须重做本节。

| # | 步骤 | 入口（UI / API 等价） | 判据 |
|---|---|---|---|
| 1 | （可选）按需调整 C 预置草稿 | 医院端 → 随访计划 → 「普通起搏器术后随访」/「ICD/CRT-D 术后随访」编辑（仅未发布可改，A-FU-019；常规 / ERI 期间隔的 6–12 / 3–6 / 1–3 个月可配即在此调） | 保存写 PLAN_UPDATE 变更记录；参数与 Q03 的出入逐项与医院 C 确认留痕 |
| 2 | 发布两套预置计划 | 计划列表 → 逐个「发布」（`POST /api/hospital/followup/plans/{id}/publish`） | 状态 PUBLISHED、写 PLAN_PUBLISH 变更记录与审计（A-FU-021）；自动入组生效——保存植入记录后按 fu_plan_mapping（V86：SSI/DDD/CRT_P/HBP_LBBP/LEADLESS → 普通，ICD/CRT_D → ICD）入组，起算快照 = 植入日期（C-FU-003） |
| 3 | 核对映射 | 医院端 → 随访计划 → 器械类型映射（`GET/PUT /api/hospital/followup/plans/device-mapping`，E21-T05） | 七类器械各指向对应计划族；如产品改用其他族编码，经本页或迁移调整（OQ-135④） |
| 4 | 试入组验证 | 登记一位虚构患者（示例）+ 首条植入记录（如 DDD） | 自动入组「普通起搏器术后随访」；术后72小时任务窗口 = 植入日至植入后 7 天；历史患者（过去植入日期）不为已过窗口建任务（SKIP，Q14） |

## 4. 行级核对与防漂移

- `CPresetPlanSqlTest`（CI 恒跑，9 例）：计划行（IMPLANT_DATE / ONGOING / auto_enroll / UNPUBLISHED）、子计划三组、节点行与 Q03 表逐项（偏移 / 提醒 / 窗口 / SKIP / enroll_mode）、提醒开始 = 窗口开始、表单 code、V86 映射、PlanNodeRule 结构校验、排期示例（72 小时窗口 [植入, +7]、SKIP、enroll_mode 过滤、变更记录只建不发）。
- `CFieldDictSqlTest`（CI 恒跑，9 例）：附录 97 行 ↔ V90 逐项（81 字段落 fe_field + 植入配套 3；报告 16 由 rpt 模型承载不重复登记）、纸质表顺序（sort_no = 行号 × 10）、键位契约（f3nn / followup_date / visit_doctor / c_eri_status / 程控分组锚点）、字典绑定与带入标记、选项集互斥与并集（Q04 / Q06 / Q07）、器械上下文条件（E21-T03 DSL）、软范围与上限频率硬规则（CL-01 / C-FLD-007）、植入配套列（OQ-132②）。
