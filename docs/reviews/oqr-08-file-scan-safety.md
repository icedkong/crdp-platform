# OQR-08：生产扫描与异常文件访问实施记录

日期：2026-11-20。分支：`codex/oqr-08-file-scan-safety`。关联 OQ-154②③、E22-T15、tech-plan §10 文件安全。

## 实现与行为

生产 `application-prod.yml` 默认 clamd，服务地址必须显式配置；off、未知模式、空地址、非法端口与无限 / 过大超时拒绝启动。开发 / CI 保留显式 off，状态准确为 UNSCANNED。独立生产配置闸门同时接入应用 Bean 与早期环境检查；原有 KMS、审计归档等安全闸门保持有效。启动校验配置，实际服务可用性由每次同步扫描检查，不用配置正确冒充扫描服务已健康。

扫描适配器改用标准 `zINSTREAM`，严格解析完整 `stream: OK`，NUL / 换行终止、有界 4096 字节应答；任意 OK 后缀、异常、截断 / 超长回复均 50300。连接 / 读取均有限超时，并以整次连接关闭期限防止写阻塞或慢速应答无限等待。服务不可用时不写任何文件；异常响应和日志不包含服务原始应答。检出上传审计保留事件名与 CREATE 动作，结果修正为 DENIED，去除可能包含患者信息的文件名。

INFECTED / HASH_MISMATCH 在下载签发、旧签名实际取流和读取对象后均拒绝；预览沿用 OQR-07 的签发 / 前后取流复核。原件不移动、不删除、不绕过扫描状态。拒绝返回 40400，避免披露文件存在；旧短时链接不能豁免台账安全状态。

新增租户迁移 **V147**：补扫尝试次数、最近尝试时间、固定重试原因码和索引；已有 V139 及此前迁移未改动。未尝试文件优先，失败行按最近尝试时间轮转；逐行失败不阻塞后续文件。缺对象 / 归属异常 / 扫描异常均保持 UNSCANNED、完成时间不伪造，并登记重试；有失败行时汇总审计及租户作业为 FAIL / FAILED。实际哈希 / 扫描结果才前进到 CLEAN / INFECTED / HASH_MISMATCH；状态守卫不覆盖已完成结论或已删除文件。批量参数限制为 1–1000，逻辑日期使用北京时间。

## 权限、数据与处置边界

无新增权限模型或公共接口。预览患者范围和独立原件下载权限沿用既有控制，双租户隔离回归覆盖。只读运维清单 `deploy/checks/file_scan_progress.sql` 展示各状态数量及文件 ID / 尝试 / 原因码，不输出文件名、患者字段或对象键；须用既有授权只读账号并记录工单。

异常文件采用逻辑隔离，处置入口为只读清单 + 安全事件工单；医院授权删除仍走既有 `followup:scan:delete` 接口、原因和软删除审计，物理原件保留。没有新增“标为 CLEAN”或绕过状态的放行入口。误报解除 / 物理证据销毁需要另行安全处置决议。UNSCANNED 继续沿用既有访问权限 / 范围，不伪装为已验证安全。

新增 / 调整审计：`FILE_SCAN_UNAVAILABLE`（FAIL）、`FILE_VIRUS_REJECTED`（DENIED）、`FILE_UNSAFE_DOWNLOAD_DENIED`（DENIED）；补扫沿用 `FILE_VIRUS_FOUND`、`FILE_VIRUS_HASH_MISMATCH`、`FILE_VIRUS_RETRO`，汇总增加待重试数量并准确记失败。全部通过 AuditLogger，只追加；扫描失败原因固定，不记录患者明文或服务原始应答。
