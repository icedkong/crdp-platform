## 问题与最终行为

旧 last_visit_date 为只增不减的快照，删除或改早最近记录后仍按旧日期排期；最新记录判定在 SQL 中硬编码 f303，无法遵守不同模板版本的日期字段。医生日期没有绑定目标，每日可能重新指向其他次数，已有目标开始后重排失败却仍会清除指令。

- EffectiveVisitDateResolver 统一解析实体日期列与记录固化模板中 followup_date 字段，未知不伪造为今天。当前器械有效、未删除、已提交记录按实际日期及 ID 排序，同日最新记录有确定顺序；历史器械记录不能发出当前切换或指定日期命令。
- 提交、修改、删除和每次排期前重算 last_visit_date，允许回退 / 清空，遗留旧快照随正常排期校正。单次重算按模板版本复用元数据，不缓存患者结果。删除或旧记录更正不自动重放旧 ERI / 医生指令。
- 日期重算只调整 ACTIVE 入组中允许重排的后续 PENDING 常规任务；无沟通、无有效草稿 / 记录及非历史日期守卫继续生效。未来窗口沿用撤回为计划中的规则，调度到点再建。已联系、已完成、历史任务保留；暂停入组只更新派生事实，不移动任务。
- V145 将待消费医生日期绑定入组、节点、次数、器械、来源记录与模式。固定和滚动节点均按原最早开启规则选择；已有合法 PENDING 目标立即整体重排，不必等新窗口开启；未建单的目标到医生窗口开启日再建。来源不再是当前器械最新有效记录、目标变化 / 已开始 / 已联系时明确冲突，指令保留供重新确认。
- 后端按北京时间验证日期。普通任务的新指定必须晚于本次实际日期且不早于今天；历史 BACKFILL 的过去下次日期仅归档，不发出当前命令。显式重选不能空指令、不能从旧器械或非最新记录发出，也不能借历史例外接受过去日期。
- 创建 / 重排、指令消费和审计同事务提交或回滚；V146 的任务来源留痕保留已生效医生排期，后续实际日期或起算日重算不会把它改回默认日期。记录修改中未改变的历史指定值不重新发出命令。
- 指定目标通过同一服务覆盖调度与月度统计投影；医生窗口开启前不按默认日期提前建任务，缓存可呈现绑定后的真实日期。原 ±30 天窗口、开启日和一次消费算例保持。

## 接口与界面

原提交及修改接口增加可选 reselectNextVisit；只有医生显式重新确认才重新选择后续合法次数，baseVersion 与修改原因要求不变。false / 未传不进入补录摘要的新字段，保持旧请求摘要形态；true 进入摘要，避免混淆两次不同请求。

记录详情附 doctorNextCommands（标识均为字符串、旧缺失绑定可为 null），展示待消费 / 冲突状态。记录页提供显式重新确认入口，未改表单字段也能保存确认；成功后重读服务端状态，切换记录清理旧状态。绑定状态和确认标记不写入临床 JSON 或本地草稿。

真实挂载测试同时发现并修复原修改流程缺少 startRecordEditSession / updateSubmittedRecord / deleteRecord 导入，以及修改原因未传给保存请求的问题。历史指定值未改动时，不因保存其他字段而被当成新的过去日期拦截；新日期和显式重选仍校验。

## 权限、范围与审计

沿用记录、器械和计划的既有模块 / 功能开关、权限、乐观锁及患者范围，越范围维持 40400；没有新增公开端点或明文读取能力。新内部 Mapper 逐项声明 IgnoreScope 理由，只供已校验患者范围的业务入口和按租户执行的调度使用，不暴露全院记录查询。器械、记录及调度共享患者锁，并在锁后核验当前入组，避免遍历后暂停 / 切换竞争；已绑定日期及已生效医生任务也受起算日期纠错保护。

新增 LAST_VISIT_RECALC、DOCTOR_NEXT_BIND、DOCTOR_NEXT_CONSUME（对象 ENROLLMENT）与 DOCTOR_NEXT_REVOKE（对象 FU_RECORD）审计。只记录对象标识和操作说明，不写临床 JSON、姓名或联系方式；与业务事务一同回滚。新增迁移 V145 / V146，没有修改旧迁移、增加 tenant_id 或伪造历史指令目标。
