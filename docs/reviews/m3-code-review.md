# 临床科研数据一体化平台（crdp）M0–M3 代码审查报告

> **2026-11-10 补记：** B1（生产 KMS 未接入）对演示的绕过已经由 [PR #205](https://github.com/icedkong/crdp-platform/pull/205) 的 demo 模式落地：演示使用本地 AES-256-GCM 信封加密和模拟短信，不再在演示路径上返回 501。**B1 与 B2 暂缓**，不在本轮处理。下面正文是审查当时的结论，没有改写。

审查对象：`icedkong/crdp-platform` 的 `main` 分支，提交 `aa9ba2e`（2026-11-10）。  
审查方式：只读。对照 `docs/tasks/tasks.csv`、需求规格、设计规范和接口约定核对实现；抽查安全、随访业务、前端和测试。没有改业务代码，没有向 `main` 推送。  
本次没有在本机重跑全量构建。GitHub Actions 上，`de71854` 及之前若干次 `main` 流水线是成功的；`aa9ba2e` 的流水线在审查时仍在跑。流水线内容是 Flyway / 基线脚本、后端测试（含连 MySQL 的集成测试）、前端格式、lint、测试和构建。流水线里没有 SAST、依赖漏洞扫描或镜像扫描。

判定口径：

- **已完成**：仓库里有对应实现，关联需求的主要验收在代码和自动化测试里能对上。
- **部分完成**：有代码、脚本或手册，但验收标准没有达到，或只在文档 / 本机替身里“通过”。
- **缺失**：没有可交付的实现，或文档自己写明尚未落地。

“已完成”只表示代码层面。它不等于医院已经验收，也不等于华为云上已经开通。

## 1. 总体结论

**不能进入医院 A 上线阶段。**

医院 A 的主流程在代码里大体已经搭起来：按医院分库、登录和权限、数据范围、默认脱敏、表单模板、随访计划与任务、报告单位置、两分钟自动保存、按节点的随访率、5000 名虚构患者的导入测试，这些都能在仓库里找到真实实现，而且测试不是空断言。提交记录把 M0–M3 的每个任务都标成了一次合并，这个“全部完成”不能当成上线结论。

挡住上线的是下面几件事，任意一条都够：

1. 生产环境的密钥服务没有接入。生产配置强制走 KMS，对应实现一调用就返回“尚未接入”。患者姓名、病案号、电话无法在生产环境加密入库。
2. 审计“在线留 1 年、归档锁定 15 年”没有在生产配置里打开。默认是不归档。
3. M3 的出口（技术方案：UAT 通过、渗透高危清零、恢复演练达标）没有发生。仓库里是自查手册、缺陷入库脚本，以及在本机 MySQL 上算出的 RPO 1 秒、RTO 9 秒。第三方渗透报告和医院签字都不存在。监控告警（任务 E22-T03）文档写明尚未落地。
4. 还没挂到患者身上的文件，本院任意已登录用户可以按文件编号预览。一次性上传令牌会整段写进访问日志。

因此：可以把当前 `main` 当作“医院 A 功能开发的候选版本”继续修缺陷、补上线前安全项；不能把它当作 M3 已经验收、可以切正式数据的版本。

## 2. 问题清单

严重程度：**阻断**（不上线就不能过）、**严重**（上线前必须处理）、**一般**（应排进修复，不单独否决上线）、**建议**（整理项）。

### 阻断

#### B1. 生产加密不可用，患者敏感字段无法入库

- 位置：`backend/crdp-framework/src/main/java/com/crdp/framework/crypto/KmsKeyProvider.java` 第 10–21 行；`backend/crdp-server/src/main/resources/application-prod.yml` 第 3–4 行。
- 违反：A-NFR-003、C-NFR-003；任务 E03-T02（每院独立数据密钥，明文密钥不落盘）。
- 事实：生产剖面把 `crdp.crypto.mode` 设为 `kms`。`KmsKeyProvider` 的生成密钥和解包直接抛出 501 / 50100「KMS 密钥服务尚未接入」。本地用的是配置字符串派生的 AES-256-GCM，算法本身是真加密，但不能拿到生产去用。进程可以启动，第一次加解密才失败。
- 建议：KMS 未接通时，生产剖面应启动失败。接入华为云 DEW 后再允许 `mode=kms`。在此之前不要用该版本承载真实患者。

#### B2. M3 出口被写成了已完成，渗透、UAT 和云上恢复都没有发生

- 位置：
  - `docs/ops/pentest-remediation.md` 第 4–6 行、第 78 行（第三方报告“待窗口内回填”；窗口写的是 2027-06-21 至 07-16）。
  - `docs/testing/uat-remediation-hospital-a.md` 第 6 行（缺陷库 0 条 UAT 问题，窗口未到）。
  - `docs/ops/drill-records/2026-11-10-local-ci.md` 第 3–7 行（写明是本机 compose MySQL 替身，不是生产云演练；同文仍给出 RPO 1 秒、RTO 9 秒、PASS）。
  - `docs/ops/cce-prod.md` 第 11–12 行（E22-T03 监控告警、E01-T06 开发测试网络“尚未落地”）。
  - `docs/requirements/tech-plan.md` 第 924 行（M3 出口：UAT 通过、渗透高危清零、恢复演练达标）。
- 违反：E22-T03、E22-T05、E22-T07、E22-T09、E22-T10、E22-T11、E22-T12、E23-T08、E23-T09、E23-T10、E19-T10；NFR-SEC-006、NFR-AVL-002。
- 事实：这些提交里有真东西：IaC 草稿、恢复脚本、关掉生产 Swagger、短信回执可配 Basic Auth、UAT 脚本和自查修复（例如补授权的迁移）。验收原文要求的是第三方报告、医院签字、云上主备切换和跨区域恢复实测。仓库自己的手册也把这些留成人来做。提交标题容易被读成“已经验收”。
- 建议：对外口径改成“上线前材料已备，云上动作和医院验收未做”。M3 出口以第三方报告、UAT 签字单和生产演练报告为准，不以本机演练数字为准。E22-T03（CES 告警与 LTS）要单独补，后面的生产集群手册依赖它。

### 严重

#### S1. 未挂到患者身上的文件，本院任意登录用户都能预览

- 位置：`backend/crdp-followup/src/main/java/com/crdp/followup/file/api/FileController.java` 第 71–75 行；`ContactAudioScopeGuard.java` 第 28–31 行；`ReportFileScopeGuard.java` 第 28–31 行。
- 违反：数据范围默认拒绝（AGENTS.md 第 5 节第 2 条）；A-NFR-005。
- 事实：预览链接接口只要医院登录且开通随访模块，不要求报告单权限。文件已经挂上沟通记录或报告单时，会按患者范围返回 40400。没挂上时（上传后还没保存进报告单、手机上传尚未提交），两处守卫直接返回，等于放行。文件编号是自增的，可以按号尝试。下载走同一套“未挂即放行”，只是下载多要一个 `followup:scan:download`。
- 建议：未关联文件只允许上传者本人取预览和下载链接。已关联文件维持现在的范围校验。

#### S2. 一次性令牌写进访问日志

- 位置：`backend/crdp-framework/src/main/java/com/crdp/framework/web/RequestLoggingFilter.java` 第 31–36 行。
- 违反：AGENTS.md 第 5 节第 5 条（日志不写令牌）。
- 事实：过滤器对每个请求记录“方法 + 完整路径 + 状态”。手机上传的路径里带 256 位令牌（`/api/h5/upload/{token}`），预览和签名下载的路径里也带令牌。持有日志的人，在提交前的 15 分钟内可以用该令牌按签发人的身份上传。令牌在提交后才会作废；提交前可以多次使用（这点和 OQ-117 的连拍设计一致，问题出在日志把令牌留下来了）。
- 建议：日志只记路由模板或令牌摘要。拒绝请求时也不要打完整路径。

#### S3. 审计 15 年锁定在生产配置里是关的

- 位置：`backend/crdp-server/src/main/resources/application.yml` 第 96–100 行（`storage.type: none`）。`application-prod.yml` 没有把审计归档改成 `obs`。
- 违反：PLT-AUD-010；任务 E08-T03、E22-T08（在线保留 1 年，归档对象锁定 15 年）。
- 事实：类型为 `none` 时，归档作业只补数据库分区，不上传、也不删除在线数据。WORM 桶的 IaC 和本地文件替身演练都有，生产配置本身没打开。在线审计被改时，没有一份不可变副本。行级触发器禁止改删审计行，但设置会话变量后可以放开，这需要数据库账号，应用没有改删接口。
- 建议：生产剖面缺少归档桶配置就启动失败，和业务文件桶同一标准。等保材料里不要写“15 年已验证”，除非云上保留策略真的开过且试过不能删。

#### S4. 平台视角的默认规则只存在于本机种子

- 位置：`backend/crdp-server/src/main/java/com/crdp/server/config/TenantSchemaMigrator.java` 第 83–86 行；`db/platform/seed/V109__seed_view_rules.sql` 第 1–27 行；`ViewRuleResolver.java` 第 61–67 行。
- 违反：PLT-VIEW-008、PLT-VIEW-010、PLT-VIEW-011；任务 E20-T02。
- 事实：种子只在 `local` / `dev` 执行。V109 的注释写“生产不含种子，由平台初始化时登记”，仓库里没有另一处生产迁移或开通代码去插入这些默认规则。没有规则时，解析结果回落为“可见、只读、禁止导出”。医院端姓名、证件号、手机号、病案号、住址仍按字段策略脱敏；视角规则里的“明文”也不会把已经脱敏的列表值放开。缺掉的是种子里才有的报告单原件隐藏、通话录音隐藏和 RCT 设盲。文件签发对视角会话另有硬拒绝，不完全靠这条规则。
- 建议：把 V109 的默认规则放进生产也会执行的迁移，启动时检查这些规则编码存在。

#### S5. 医生无法在界面上确认失访，也无法把患者改为失访

- 位置：
  - 后端确认接口已有：`FollowupTaskController.java` 第 161–173 行（`POST .../tasks/{id}/confirm-lost`）。
  - 任务列表页面没有对应按钮：`frontend/apps/web-hospital/src/views/followup/task/index.vue`（全文无“确认失访”）。
  - 患者状态接口只有查询：`PatientStatusController.java` 第 15–17 行、第 30–35 行。类注释写了 `POST /{id}/status` 含“失访”，方法没有实现。
  - `PatientFollowupStatusService.java` 第 14–16 行写明：暂停、恢复、移出、死亡已做，失访“随后续”。
- 违反：A-FU-012；设计 `docs/design/pages.md` 第 459 行（失访候选上医生可“确认失访”）；A-PAT-011。
- 事实：每日判定、失访候选、连续次数、每窗口最多 5 次跟进，后端是有的。确认接口会返回“请把患者改为失访”的标志，前端没有任何引用。患者级失访状态没有写入入口，所以连续两个年度失访之后，后续年度任务仍会按“随访中”继续创建。规格要求的是提示后由医生改状态，不是系统自动改；现在医生没有地方改。
- 建议：任务列表为医生提供“确认失访”。患者详情提供“改为失访”，调用新的状态接口，写状态历史和审计，并停止后续任务。

#### S6. 调度补跑可能把本该随访的任务改成“停用期间未执行”

- 位置：`FollowupTaskCreationService.java` 第 400–410 行（`effectiveCreateType`）。
- 违反：A-FU-001；任务 E14-T04（任务在提醒开始日与窗口开始日较早的一天创建，失败可补跑）。
- 事实：补跑会从上次成功日的下一天逐日走到当天，这一段是对的。改判“窗口已结束”时，用的是本次运行的目标日，不是正在补的那一天。作业如果停过窗口结束日再补跑，本来该建成普通待随访的那一次，会被改成停用或暂停期间未执行。
- 建议：改判时用正在补的那个逻辑日，不要用整次补跑的结束日。补一条“停机超过窗口再补跑”的测试。

### 一般

#### G1. 报告单“同一位置只能有一条”在数据库里挡不住

- 位置：`db/tenant/followup/V63__rpt_report_link_file.sql` 第 42–54 行。
- 违反：A-ATT-002、A-ATT-020；任务 E16-T13（同一报告单同一位置唯一）。
- 事实：表 `rpt_report_link` 已建，一份报告单可以挂多个位置，位置可以是基线分类或随访记录的整条 / 分组，上传至少要选一个位置，没有位置行的归入“未指定位置”，模板改版有退回作业。这些和规格一致。唯一索引含可空列。MySQL 里 NULL 互不相等，同一报告单的两条“整条随访记录”（锚点为空）或两条基线分类（记录 id 为空）可以同时插入。服务层只对单次请求去重。
- 建议：用生成列把空值换成固定占位，再加唯一索引。不要改已经执行过的 V63，另写新迁移。

#### G2. 窗口内完成率没有按实际随访日期计算

- 位置：`NodeOccurrenceFactCalculator.java` 第 324–327 行。
- 违反：技术方案第 757 行、A-DASH-012 / Q38（窗口内完成率 = 实际随访日期落在窗口内，含首尾）。主随访率的口径（逾期完成和补录计入已随访）是按规格做的。
- 事实：已完成任务的“是否在窗口内”看的是完成方式是不是“按时”，而完成方式按提交当天计算，不是表单里的实际随访日期。补录任务被强制标成补录，窗口内完成率恒为 0。这是参考指标，主随访率不受影响。
- 建议：窗口内完成率改为比较实际随访日期和窗口起止。补录若日期落在原窗口内，参考指标应计入。

#### G3. 患者详情缺少“操作日志”页签，报告单页签不看功能开关

- 位置：`frontend/apps/web-hospital/src/views/followup/patient/detail.vue` 第 166 行、第 999–1003 行。接口已有：`HospitalAuditController.java` 第 63–70 行。
- 违反：`docs/design/pages.md` 第 4.1、4.9 节（操作日志总是显示）；第 4.1 节（报告单随功能开关 `report` 隐藏）。任务 E24-T04 的手机验收含各页签。
- 事实：基线资料和随访记录已经用左栏附件导航；顶部分类条有已填 / 应填，未填完用警告色，点击会滚动高亮。这和设计是对齐的。页签目前只有基线、随访记录、报告单、沟通记录。操作日志接口没有接到页面上。报告单页签没有判断开关。
- 建议：补操作日志页签，默认每页 20 条。`report` 关闭时不渲染报告单页签。

#### G4. 界面主色配置写了 #3A75FF，运行时会被另一套色板换掉

- 位置：`frontend/apps/web-hospital/src/app.vue` 第 34–40 行；`frontend/packages/effects/hooks/src/use-design-tokens.ts` 第 37 行；`frontend/packages/@core/base/shared/src/color/generator.ts` 第 18 行。平台端 `app.vue` 同样。
- 违反：`docs/design/design-system.md` 第 1.1 节；`docs/design/tokens.ts` 中 `colorPrimary = #3A75FF`。
- 事实：主题令牌先写入 #3A75FF，随后被 `hsl(var(--primary))` 盖掉。`--primary` 取的是色板的 500 档，不是传入的原色。圆角、边框和页面底色也被 Vben 的 CSS 变量盖过令牌。外壳仍是官方 Vben Admin 5，只用 Ant Design Vue，侧栏和顶栏没有另写一套。没有引入 Element Plus、Naive UI、TDesign。
- 建议：业务色以 `tokens.ts` 的 Ant Design 主题为准，不要用色板 500 档回写主色、成功色、警告色和错误色。

#### G5. 基线详情右侧写死了一块出院登记字段

- 位置：`detail.vue` 第 1077 行起，标题“基线信息（出院登记）”，含姓名、编号、性别、年龄、病区、手术日期等。
- 违反：设计规范第 6.2 节（字段由模板驱动，页面不写死业务字段）。随访录入和基线分节编辑已经走表单渲染器。
- 建议：详情右侧只保留模板只读渲染。姓名和病区留在页头。登记用的固定字段如果产品确认不进模板，写进 `docs/open-questions.md`，避免和模板各维护一套。

#### G6. 报告单水印只盖在页面上，取文件字节时没有水印

- 位置：预览组件与 `frontend/packages/viewer/src/watermark.ts`（文案为“姓名（账号）· 医院名称 · 预览时间”，精确到分钟，并有防删）。取流接口返回对象存储里的原始字节。
- 违反：A-FU-025、A-ATT-005 里“预览带水印且不可关闭”的强度，取决于是否接受“只约束页面”。
- 事实：使用查看器的页面关不掉水印。拿到 5 分钟预览链接的人可以直接请求文件，内容上没有水印。
- 建议：若上线要求水印跟着文件走，在预览代理里烧录；否则在验收说明里写明“水印只在页面，直链是原件”。

#### G7. 持续集成没有安全扫描

- 位置：`.github/workflows/ci.yml` 全文。有单元测试、集成测试、前端 lint 和构建，以及若干防文档漂移的 Python 检查。没有 CodeQL、依赖漏洞扫描或镜像扫描。仓库里也没有合并请求模板。
- 违反：任务 E01-T04（高危漏洞阻断合并）、E01-T01（主干保护与合并请求模板）。
- 建议：加上依赖扫描和镜像扫描，高危失败即阻断合并。分支保护在 GitHub 仓库设置里打开，不在本次代码审查范围内核实。

#### G8. 打开一份大表单会按选项集逐条查库

- 位置：`backend/crdp-form/src/main/java/com/crdp/form/record/app/FormService.java` 第 849–863 行。

## 3. 对照审查问题的结论（做得对的部分）

下面这些核对过，当前实现和规格一致，不单列成缺陷。

**租户隔离。** 没有租户上下文时数据源直接拒绝，不回落到平台库。登录之后用的是会话里的医院，不接受请求参数里的租户。医院账号进不了平台接口，平台账号也进不了医院接口。定时任务按医院逐个执行，并在结束时清理上下文。

**权限与数据范围。** 缺权限返回 40300。受控表的查询在启动时检查必须声明数据范围；范围为空时查询结果为空；越范围看单个患者返回 40400。业务代码里没有 `if (租户 == "A")` 这种分支，医院差异走功能和配置。

**脱敏与审计。** 列表默认脱敏。明文要 `followup:patient:plain`，并写访问审计，审计里不存明文。明文查看不要求再次输入密码，这是已确认的 OQ-57，不记为缺陷。审计只有插入，有哈希链，没有改删接口。敏感操作的审计由调用方传摘要，框架不会自动把正文打成摘要，以后新增审计点时要继续遵守。

**平台视角的双人复核是代码，不是只有文档。** 发起人不能批自己的规则变更；高敏变更（放宽为明文、改为可编辑、允许导出）走复核。视角会话默认只读，导出和原件签发有单独拦截。

**随访计划。** 任务开启日取提醒开始日和窗口开始日中较早的一天。每天北京时间 00:10 调度，启动时补跑。窗口在入组前已经结束、且节点配置为补录的，入组当天建成补录任务。死亡会终止未完成任务并不再创建。通话录音会生成通话记录报告单，并挂到该任务已有的随访记录上；还没有随访记录时进入“未指定位置”。

**自动保存。** 有改动才每 2 分钟写服务器草稿；每 30 秒和失焦写本机草稿。版本冲突返回 409 并暂停自动保存。草稿不提交、不写字段历史。

**表单。** 随访录入和基线分节由模板渲染，不是在页面上铺 266 个字段。Enter 不提交，Ctrl/⌘+S 暂存，Ctrl/⌘+Enter 提交。

**上传。** 扩展名白名单，并用文件内容判断真实类型，改扩展名的可执行文件会被拒绝。对象键不用用户提供的路径。

**SQL 注入与 XSS。** 抽查到的排序和检索列来自白名单或代码目录，值走参数绑定。医院端业务页没有把患者输入交给 `v-html`。

**前端外壳与适配。** Vben 默认侧栏、顶栏、多标签页。手机上只有患者列表、患者详情、随访录入、我的任务、报告单、基线分节编辑放行，其余页面是“请在电脑或平板上操作”。橙色主要用于未填完、未指定位置和视角提示条，没有用作主按钮。

**测试。** 抽查的后端测试会断言业务结果。5000 名虚构患者的导入、回滚，以及 M3 主链路，是连数据库的集成测试，随 CI 在 `CRDP_IT_MYSQL_PORT` 打开时执行。渗透和 UAT 的 Python 检查只核对手册章节是否还在，不能代替外部验收。

**虚构数据。** 未发现真实患者身份信息，也没有医院样例表或竞品截图进仓库。

## 5. 上线前建议的处理顺序

1. 接入 KMS，或在接通前禁止生产剖面启动。不要导入真实患者。
2. 收紧未关联文件的预览和下载，并停止把令牌写入访问日志。
3. 生产配置打开审计归档，缺桶就启动失败；补上视角默认规则的生产迁移。
4. 补“确认失访”和“患者改为失访”，并修正补跑改判和报告单唯一索引。
5. 窗口内完成率改为按实际随访日期；补操作日志页签。
6. 监控告警、依赖与镜像扫描、生产主备和跨区域演练，由持云账号的人做完并留记录。第三方渗透和医院 UAT 未完成前，不宣布 M3 出口通过。
