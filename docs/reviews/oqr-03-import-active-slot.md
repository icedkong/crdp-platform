## 实际改动

- 新增租户随访迁移 V140：`imp_job.active_slot` 为状态派生列，UPLOADED / PRECHECKING / IMPORTING 为 1，其余 NULL；`uk_imp_job_active_slot` 唯一索引按各租户数据库互斥。没有新增 tenant_id 或持久业务表，没有修改旧迁移。
- 创建直接插入并由数据库裁决；创建、确认与重试的唯一约束竞争统一返回既有 40901 和原有提示文案。`countActive` 仅保留作观测接口，生产创建入口不再依赖先 COUNT 再 INSERT。
- 确认沿用现有事务，争用失败不保存选项、范围或切批结果；事务整体回滚时状态和槽位一起恢复。PRECHECKED 不占槽，用户可以保留多个预检结果，确认时重新竞争。
- 重试在请求线程调用 `prepareRetry` 完成 PARTIAL_FAILED → IMPORTING 的 CAS，再派发已有异步执行入口；不会先受理再吞掉后台竞争异常。同作业重复重试也只能一方成功。
- 预检完成 / 失败、取消、提交终态随原状态写入自动释放，无额外解锁步骤。异常中断继续保留活动槽，未新增超时解锁或自动接管，防止尚在执行时重复导入。
- 上传竞争失败沿用原始对象清理；增加 IMPORT_UPLOAD / IMPORT_COMMIT / IMPORT_RETRY 拒绝审计，不记录原始文件内容或数据库异常原文。未改变权限码、模块开关或患者数据范围模型。

## 迁移与部署边界

V140 先通过本连接的临时校验表验证活动行数；超过一条时阻断，不自动挑选赢家、改变状态或删除数据。最终唯一索引继续覆盖预检之后的写入竞争。

上线需维护窗口，逐个已开通随访模块的租户执行 [只读检查 SQL](../../deploy/checks/import-active-jobs.sql)，按 [处置手册](../ops/import-active-jobs.md) 核实在途执行与批次。没有可靠恢复入口时保持阻断，不能凭更新时间手工改状态解锁。生产环境尚未执行上述步骤。
