## 解决的问题

旧预览只推演源包行数，没有读取目标库；旧应用会覆盖同版本计划并删除重建节点，可能使已有入组、任务引用的定义改变或丢失。现将开通初始化与在用更新分流，并让预检与执行使用同一确定的内存应用计划。

## 实际行为

- 新增 `POST /api/platform/config-templates/{id}/preview {tenantId}`，权限沿用 `platform:tenant:create`。目标库只读事务计算真实新增、更新、保留、丢弃及冲突；返回行序号、字段名、原因、分表计数和 `planHash`，不返回配置值。
- 公开 apply 必须传 `{tenantId,planHash}`。摘要绑定模板 ID / 内容、目标租户、操作人、可分配范围及目标配置快照。执行在 REPEATABLE_READ 事务中锁定配置并重新生成同一计划；缺失 / 失效摘要返回 40900，冲突返回 40901。
- 在用更新保留所有已有计划版本与节点 ID，采用比“只保护已引用版本”更保守的策略，避免检查引用后又有新入组的竞争。相同内容复用原版本；不同内容创建同族递增的 `UNPUBLISHED` 版本，须另行审核发布，不自动迁移入组。
- 已有表单发布快照不得改写或追加字段；不一致时阻断整包，要求在源端发布新版本重新导出。其他配置按预览对账更新，包外配置保留；新行用户引用置空，已有目标行的本院操作人保留。
- 新租户开通通过内部 `initialize` 入口，仅允许 PROVISIONING 租户，继续使用原初始化合并逻辑。该入口不暴露为公开 HTTP 选项。
- 弹窗选择目标后读取预检；加载、失败或冲突时禁止应用。切换目标 / 模板清空确认、忽略旧响应；提交失败重新预检并要求再次确认。展示行级差异及分表预计计数。

## 安全与数据边界

新增平台 `CONFIG_TEMPLATE_PREVIEW` 成功 / 失败审计，应用拒绝 / 事务失败补 APPLY FAIL 审计；摘要、字段名与原因不含配置值。未新增明文接口、权限码或数据范围豁免。目标读取只涉及配置表，不查询患者 / 任务业务表；不对存量患者、入组或任务批量写回。无数据库结构变更，无新增或修改迁移。
